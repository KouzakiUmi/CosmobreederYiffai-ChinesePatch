## 一、目标与验收分层

本项目目标：**在原版 Java/libGDX 二进制上做源依赖差分补丁**，让剧情、无线电、UI、道具与结局可读成通顺中文，且不改动玩法条件、施受关系、信息揭示顺序与保护字段。

## 二、关键事实与取舍

### 基线与归档

- 原版基线以 `localization/sources/archives.json` 为准，`backup/` 保存对应副本。
- 归档格式：`cosmobreeder-multi.jar` + `patch.pak`；编号条目无扩展名，用 `localization/tools/codec.py`（Salsa20）解密；**patch.pak 覆盖 jar 同键**，`datay` 只在 jar。

### 改文落地与台账守卫

改文一律写来源锁定台账（`localization/translations/*-repairs.jsonl`），由 `tools/editorial_repairs.py` 校验应用；任一 SHA 或旧值漂移整批拒绝。台账是构建门禁与回验依据，不可手动编辑。

### 容器归属与折行规则（本阶段重点）

反编译证实候选产物中 `PRG/JR`／`PRG/Nb` 已调 `DialogueWrap.radio`／`story`，中文实际走 `PixelLayout`：
- **故事框**：240px / story12，满行 20 汉字，每页 3 行；
- **无线电**：150px / bbc2 10px，满行 15 汉字；
- `<TomcatItems.*>` / `<BossuDex.*>` 物品说明**走无线电**而非故事框（调用链：`JB → JM → JQ → JR → DialogueWrap.radio`）。

## 七、重建与恢复步骤（当需要重新构建/推演时）

1. **确认基线**：`localization/sources/archives.json` 的英文源；如有差异先从 `backup/` 恢复。
2. **检查组件配置**：`localization/optimization/r28/r9polish/component.json` 的 `batches` 指向的 ledger/gate/decisions 是否完好，SHA 是否与封签一致。
3. **构建候选**：`build_candidate.py --output <new-dir>`（目录必须不存在）。
4. **17 步 CPU 回归**：`test_candidate.py`；确认 `exit_code` 全 0、`status` 正确。
5. **台账回验**：`verify_readback.py <new-dir-name>`；无问题时才继续。
6. **封签**：`finalize_r9_acceptance.py`；再读 `acceptance.json` 核对 archives SHA 与 build-manifest。
7. **发行打包**：`build_alpha_release.py`；对生成的 EXE 复跑 `--verify-payload` / `--licenses`；校验 `SHA256SUMS`。
8. **只读核验（可选但推荐）**：对新快照重做一次推送前交叉核验（台账、gate、封签自洽、计数管线）。

失败恢复要点：
- 若 build 报错（字节码不一致、基线漂移）：停手，检查 component.json 索引与 ledger SHA；不要强行覆盖。
- 若 CPU 回归某一步退出非零：先定位哪一步（如 dialogue-wrap、compact 等），查看对应的测试输出与日志，按错误类型决定修复代码还是调整台账。
- 若回验发现问题：逐条检查 `occurrence_id → unit_id → source`，必要时补修台账或撤回一批次。
- 若发行打包提示 payload 校验失败：说明 delta 与目标不匹配，回到步骤 2–5，确保台账与组件未漂移。
