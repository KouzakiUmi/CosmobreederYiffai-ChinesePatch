# 中文字体、布局与句子连贯性审计

适用：Cosmobreeder Yiffai 1.0.5_full；alpha0.1 / r27-story12-shaderfix-test5。日期：2026-10-25。

## 结论

**当前补丁不能覆盖全部中文显示情况。正文适配有效，但它不是全局排版接管；真实游戏代码的隔离执行已经复现姓名笔画重叠，语料和资源审计还确认了续句、分档漏译和固定图片缺口。**

本轮没有修改正式译文、补丁运行源码、游戏归档、安装目录或存档；新增的只是本审计目录中的报告、探针、录制、原图裁剪及工单。没有启动游戏、GL、Steam或部署补丁。

关键结果：

1. **特殊语言字体：实际复现严重缺字。** PAK中268条含汉字的Fox／HardFox命令，在原游戏选择dingbats的条件下全部4735个汉字均无直接字形；真实parser→jo→arr探针测得230条命令没有任何可见的非空白字形。原测试对该分支跳过墨迹检查，因此正文测试通过不能排除此问题。
2. **姓名／存档：实际复现。** 对最终游戏类输入八汉字合成姓名，实际 LY、Mb、Id、arr、arq 调用产生可见笔画交叠11个逻辑像素。不是仅根据字号推测；也不是用户实际存档截图。
3. **道具分割线：本轮样本没有复现遮挡。** 已登记名称和两行说明的CPU绘制均落在原框内，分割线与文字墨迹交叉为0。但背景、父裁剪、所有选择位置与CRT并未全面验收，不能据此保证所有状态。
4. **句子连贯性仍有明显缺口。** 956组合句只覆盖DS，不覆盖VSN。VSN另发现421条待审相邻续句边：349条普通正文、72条特殊字形角色行。它们是审校候选，不是421个已确认缺陷，更不能全部自动拼接。
5. **两种资源档不能共用覆盖结论。** JAR字典871键、含汉字值0；PAK字典1012键、含汉字值926。SFW成功套用834组合句，122组按来源门禁跳过；另有460行对白未匹配到规范语料。SFW的39份VSN脚本／792条字幕行还与原版保持相同entry字节、没有汉字。
6. **图片工单已实际导出。** 38组逻辑工单、243条目标归档／区域记录、1402张原尺寸RGBA裁剪；还列出803项固定图的覆盖状态和775组幕间待核清单。裁剪数量不代表人工审过全部图片。

入口：[模拟渲染说明](<simulation/README.md>) · [CPU六场景总览](<simulation/cpu-contact-sheet-2x.png>) · [图片翻译工单](<image-workorders/README.md>) · [语料审计](<text-review/README.md>)。

## 2. 游戏实际怎样绘字

```text
.ds / .vsn / 字典 / class常量
  → 解析、Tc/SA替换、局部大写化、原字符配额或新分行
  → 场景消费者：Id逐字 / 整行 / 各自手工切块与居中
  → SN / Yg
  → arp字体 → arr字形布局 → arq顶点缓存 → ars批提交
  → 场景FBO、终端shader、合成与最终缩放/CRT
```

FNT只提供字形度量，不知道道具栏分割线、图标占位、父clip或鼠标区域。Yg的常用单行入口没有开启底层自动wrap，场景如果事先截断，末端换字体不能找回内容。原链依据见[底层绘制与顶点](<../字体渲染逆向与补丁指南.md#L198-L238>)；本轮还保存了[最终r27反汇编](<simulation/real-methods-javap.txt>)。

| 字体角色 | 当前中文／ASCII advance | 字形／FNT行高 | 实际使用边界 |
|---|---|---|---|
| default | 中文10，ASCII／空格8 | 中文10×10；行高14 | 大量旧UI、无线电、Continue；外层仍可能8px行距或逐字步进 |
| story12 | 中文12，ASCII／空格8 | 中文12×12；行高16 | 仅jo／Na精确整行入口；整页决定角色，中文锚点局部左移8 |
| classic | 中文8，ASCII经原等宽设置 | 中文8×8；行高8 | 道具选中名／说明、结算表、部分资料册及原有classic控件 |
| dingbats | 原图案角色、无中文字形 | 当前FNT行高10；wrapper8；id0为零尺寸fallback | Fox／HardFox条件分支；已复现中文不可见，不应直接改成提前明文显示 |

**名义字号、字形墨迹、advance、FNT行高、wrapper行距、消费者行距是六个不同量。** story12使用整页角色，所以动画只显露英文前缀或全空格时不会跳字体；但别处的中文识别条件不一致，标点独立页、扩展汉字和未来动态内容还须单独测。

本轮草稿字符集2394个码点在default、classic、story12的静态字符表均无缺字；这不包括任意玩家输入、动态替换及Locale大写变换。底层仍是BMP／UTF-16 char表，扩展区汉字、Emoji和组合序列不能据此承诺支持。新布局遇未知字形可能抛异常，旧底层没有系统字体兜底时可能直接跳字。参见[字符表检查](<inventory.json>)、[原引擎缺字分支](<../字体渲染逆向与补丁指南.md#L152-L160>)。

## 4. 实际模拟渲染的判定

使用最终r27 class，执行真实场景方法，再让原arr/arq生成CPU顶点；字体与像素取最终FNT／图集，不用系统字体替画。构造器被隔离，输入为合成对象；不调用存档服务。六场景596个实际顶点，禁止API尝试为0。详见[探针源码](<simulation/CpuEvidence.java#L60-L118>)、[录制](<simulation/cpu-recording.json>)、[分项测量](<simulation/render-report.json>)。

### 4.0 特殊语言角色：已复现零尺寸fallback导致不可见

最终PAK有Fox262条、HardFox10条命令，其中258＋10条含汉字；JAR对应272条仍为英文。原jo选择条件是`HardFox || (Fox && !readable)`；story12在pattern为true时直接转发原Id，仍使用dingbats。该字体不含中文，id0 fallback的宽／高均为0、advance8，因此不是“系统自动补字”，而是看不见的占位。归档计数、原FNT记录、parser／jo精确字节码和SFW39脚本原样证据见[独立静态复核](<pattern-static-review.json>)。

本轮读取两档106脚本并调用真实VSN parser，按其anp命令原style执行jo行绘制和原arr。`readable=false`夹具下，268条含汉字命令的4735个汉字全部无直接glyph，**230条命令连非空白可见字形盒都没有**；其余命令只剩受支持的拉丁字形等，不代表中文可读。HardFox10条在这一探针中也全部无可见字形。详见[探针统计／逐命令样本](<pattern-regressions/results.json>)、[真实运行日志](<pattern-regressions/runtime.log>)及[源码](<probes/PatternProbe.java>)。

这是已部署文本与实际字体路由的失败，不只是任意输入反例；但仍不是进入完整游戏画面后的截图。Fox可读态是另一条路径，不把不可读态结果泛化给它。原测试在pattern分支只断言角色／锚点、跳过墨迹，见[测试分支](<../../localization/layout/tests/SubtitleLayoutTest.java#L155-L173>)。

修复须保留双表示：未解读／强制符号态使用合法的原符号输入或经过验证的编码映射；允许解读时才展示对应中文。**不能把所有中文直接塞进dingbats并显示明文，破坏原语言可读性条件。** 每条路径必须校验最终字体的实际可见笔画，不只校验角色字符串。

### 4.1 姓名：已复现笔画碰撞

[存档合成帧](<simulation/save-original-eight-cjk-4x.png>)和[命名合成帧](<simulation/name-original-eight-cjk-4x.png>)均输入“宇宙育种探索先锋”。真实LY／Mb经Id逐字+8，但字形是10×10：姓名总跨度66px，七对相邻字形盒交叉140px；**真实alpha墨迹交叉11个唯一像素**。这说明只换default字库未完成紧凑字段适配。

注意：LY整卡还包含原ASCII上下行的透明padding，因此整卡字形盒交叉252px，不应全算姓名或可见碰撞。性别图标与文字盒相交3px，实际墨迹相交0；本轮不能声称性别图标已遮住姓名。中文姓名通过正常输入界面是否可达，未由这个合成夹具证明。

### 4.2 道具：指定样本分割线不相交，但不是全菜单验收

[道具合成帧](<simulation/item-classic8-selected-4x.png>)采用登记Lg／Lb：选中名基线70是测试supplier，不是所有选择项的真实y证明。真实SN经LayoutBridge补偿后名锚为177、说明锚为137；**最终顶点**说明x136..248，两行屏幕盒y201..209、209..217；原图集字形墨迹分别在201..208、209..216。

背景高192、锚(0,0)，在224高逻辑平面顶部位于32。背景局部y161的横线因此在屏幕y193，不能误拿161和正文屏幕坐标直接比较。本轮文字墨迹与分割线交叉0，名称、说明字段墨迹交叉0。

六场景图只证明classic8方案在此两行／选择位夹具下几何合理。后续独立[42格真实选择器探针](<simulation/item-selector-addendum.json>)执行了原Ld坐标表、aag/aab及Le名称y供应链：名称y实际为174／150／126／102／62，分别覆盖7／7／7／14／7格，**y70根本不在正式42格输出中**。五个真实类别是x136处的硬编码英文ARMS／HEAD／BODY／SPCL／USE；六场景图中的“装备”x56是合成消费链对照，不是正式类别定位。

因此42个位置供应器已取证，但42件正式译文、物品图标与名称墨迹交叉、装备／滚动／闪烁、真实父clip、后绘面板及shader扩张仍须回归。**“背景不透明”不等于遮挡；先画的黑底与文字重合是正常的，只能结合顺序判定遮蔽。**

### 4.3 正确对照

[story12对照](<simulation/story12-full-width-control-4x.png>)20个汉字经真实顶点占宽240px、墨迹交叉0；首盒x7、末端247，不能把理论锚点8直接当最终首盒边界。整串default10的[对照帧](<simulation/default10-whole-line-control-4x.png>)也不发生同样字间碰撞，进一步把根因定位到旧逐字8步进，而非“引擎不能画10px”。

所有这些均是**未经过shader／CRT的CPU重放，不是实机截图**；背景锚点按已证调用重放，不是执行完整父场景。

## 5. 中文断行与句子连贯性

### 5.1 必须分开的两个问题

- **视觉软换行：** 文本太长时在框内换到下一行。中文按字换行本身正常，不等于语病；长句不可能无条件放进窄栏单行。
- **源命令硬断：** 原英文把半句话拆成不同text／对话节点，中文翻译也按碎片处理，造成词组被拆、缺上下文、必须多点一次才能接上。应从来源层重构完整句，不靠末端删除换行猜回原文。

目前DialogueGrid先由PixelLayout分行，再清掉各行中的换行符以序列化回旧网格；**这不表示硬换行被忽略**。CR/LF/U+2028/U+2029仍是核心的显式断行。`<p>`属于三参格式器段落语义，`|`属于部分UI四参格式器，不能全局互换。见[网格序列化](<../../localization/layout/src/cosmoloc/layout/DialogueGrid.java#L37-L64>)。

### 5.2 合句现状与缺口

- DS台账956组／1098条合并边，来源与译文指纹校验自洽；SFW实际834组，122组来源不符跳过是正确的安全行为，不应强套。
- VSN421条待审候选中349条为普通text正文，72条为受保护字形角色行；本次候选没有auto定时边，但合并普通text仍会改变点按翻页次数。需同时审文本语义、演出块与交互步数，不能“相邻即合”。
- 另有4个VSN续行单元尚无译文。SFW的39个脚本／792文本行与PAK的67个脚本／2388文本行不同，不能套用同一物理行号。
- DS有5条刻意词中断未进入已记录的跳过清单，应补齐审校记账，而不是强合。另有中文词内英文连字符等草稿残留需逐条审。

逐边来源、短样本、特殊角色与演出上下文见[语料报告](<text-review/README.md>)和[VSN候选JSON](<text-review/results/vsn-merge-candidates.json>)；未匹配的SFW行见[变体覆盖证据](<text-review/results/sfw-variant-coverage.json>)。源码不把PAK中文UI字典复制进JAR；本轮实物含汉字统计见[身份清单](<inventory.json>)。

### 5.3 断行算法的剩余边界

1. PixelLayout已有部分中文行首／行尾禁则、英文词边界和省略号原子保护，但强制断行是可退让规则；`FORCED_BREAK`不算overflow，DialogueGrid也没有把它升级为构建失败。见[选断点逻辑](<../../localization/layout/src/cosmoloc/layout/PixelLayout.java#L278-L314>)、[禁则表](<../../localization/layout/src/cosmoloc/layout/PixelLayout.java#L483-L506>)。
2. story12还受旧28码元网格限制。二次码元封顶没有重新施加完整标点禁则；本轮合成的长ASCII＋中文标点输入，实际格式器可生成仅“，”的行。不是当前956组合句中已发现的缺陷，但是真实可复现的算法边界。
3. `ItemFont8.wrap`只按advance累加和显式分隔符切行，没有中文禁则或英文词优先级；资料册中文分支也按28／27字符切块。不能把正文核心的禁则能力算给这两条路径。见[道具wrap](<../../localization/layout/src/PRG/ItemFont8.java#L94-L116>)、[资料册切块](<../../localization/layout/src/PRG/EndingReportLayout.java#L20-L50>)。
4. 自动字幕溢出时，新PageCommand按**每页**重复原延时，完整场景会变长，不是所有时间线完全不变；应列入演出验收。见[队列与延时](<../../localization/layout/src/PRG/SubtitleLayout.java#L72-L102>)。

## 7. 字体效果与可读性

r27修正story新增2312格的透明RGB；两terminal shader按红通道判笔画，VSN版没有普通版的alpha零前置判断，所以透明白会变实心。该修复方向正确。本轮实际双归档的bbc2／classic／dingbats透明区均无alpha0且RGB非0像素，story新增格R与A掩码一致，详见[逐归档像素审计](<font-pixel-audit.json>)；但**以后仍需将全角色色通道检查作为门禁**，不能只保证这批story字格。

两shader仍有8像素周期邻域采样。它不是FNT行高，不能全局改成12／16；原CRT和最终非整数缩放也仍保留。原逻辑见[VSN shader](<../font-evidence/snapshot/shaders_vsn_term_shade.frag.txt#L27-L47>)和[普通terminal shader](<../font-evidence/snapshot/shaders_cosmo_term_shade.frag.txt#L24-L47>)。

12px正文、10px紧凑标签、8px数字／键位可作为分角色方向，但**当前classic8中文是否足够可读应单独验收**。如果道具中文改10px，必须同时调整说明行距、可见行数、矩形和交互，不能只替换FNT。classic现有8px像素已经验度量，不等于已重新证明它来自新的原生8px源；[其审计工具](<../../localization/tools/build_item_font8.py#L233-L239>)明确区分现有位图与研究用原生8px生成器。新增story12有冻结来源与OFL身份，不需要为这轮审计安装字体。

外部资料仅用于一般字体契约：通过Context7核对[libGDX BitmapFont说明](<https://libgdx.com/wiki/graphics/2d/fonts/bitmap-fonts>)的advance／fixedWidth概念；游戏混淆库没有已证准确libGDX版本，因此**不以最新版文档替代本游戏字节码**。

## 8. 固定图片翻译工单

见[可执行工单入口](<image-workorders/README.md>)、[分档JSON](<image-workorders/workorders.json>)、[CSV索引](<image-workorders/workorders.csv>)。每条绑定归档、加密entry、解密索引路由、atlas区域／index／ordinal、坐标、尺寸、Alpha和源指纹；编辑矩形是保守槽位，不冒充运行clip。

工单不仅列英文，还覆盖布局配合：

- 道具原x127／128竖线、右下y161／162横线及122×26说明槽；不能扩大字形后让其撞线。
- 存档列标题／数据列／下方面板及页脚要分区；姓名、性别和元信息不是在背景上一起擦除。

PAK仅四项继承改绘，JAR仍是各自原版像素，且不是所有对应图都具有相同文字或帧数。机器导出了351组候选的1402张原像素预览；尚未逐帧目视全部固定图与幕间，明确待核范围见[覆盖／排除表](<image-workorders/coverage-and-exclusions.json>)和[775组幕间清单](<image-workorders/scene-review-backlog.json>)。未重绘、未生成AI图片、未将任何图片写回游戏。

## 9. 建议的修复路线与验收标准

### P0：先闭合确证问题与来源覆盖

0. 先修Fox／HardFox中文与dingbats不兼容：按源命令身份保留符号输入／中文双表示，严格遵循可读性条件；将该分支实际glyph／墨迹加入门禁，不能仅让role断言通过。
1. 姓名／存档保留数据语义，改为字段布局：字形累计advance、姓名槽宽、性别、邻列、光标／高亮同一几何。不要全局把It的8改10；不要改名字存储内容来凑框。
2. 建立SFW独立来源目录，补460行未匹配对白、其自身UI字典和VSN来源；继续保留来源门禁，拒绝用PAK物理行号硬套。
3. 对349条VSN普通正文续句按完整语义段审校，生成有源身份的派生合句；72条特殊角色默认保留单独评估。保留cut／snap／rewind及翻页节奏，补4条未译续行。
4. Ew等短框在旧字符格式化／二次切块**之前**取得全文，换行与消费行数成对修复；正文必须有完整可达路径，不能只加clip隐藏越框内容。

### P1：统一度量／禁则，逐显示面接入

- 用实际字体、offset、padding、kerning与取整测量，区分glyph盒、真实墨迹和效果边界。
- 内容矩形减去内边距、图标、固定字段和描边预算；不能把240px当所有控件宽度。
- 在同一布局过程同时满足像素宽与旧码元上限；标点禁则、英文词组、成对省略号、破折号策略共用，避免二次封顶破坏断点。
- 在不溢出的前提下优先中文标点／短语边界；长句允许正常软换行，不为“每行整句”缩到不可读字号或大面积截尾。
- 排好全文再按显露索引呈现；不随打字进度重算布局，不用8px空格代替未来10／12px字重新测宽。修正前导空白显露映射，不以全局trim删除作者段落缩进。
- 自动文本和交互文本采用不同超高策略；自动字幕总时长变化必须明确验收，不能无声截断、急速轮播或无限延时。
- 道具／资料册超过容量的异常是诊断，不是用户可接受的展示后备；候选构建期尽早拦截，运行时保留全文查看途径。

### P2：位图与输出质量

按38组工单审定逐字中文，联动背景框／动态字段／选择矩形；完成深浅底Alpha验收。几何正确后再看终端8周期效果、CRT、2×／3×／4×整数倍率、非整数缩放与HiDPI，不通过关掉原场景遮挡掩盖错误。

### 每个显示面都必须分别过关

| 维度 | 必测内容 |
|---|---|
| 字体 | 实际角色、每个字形、来源许可、FNT／图集配对；未知字／替换后字符 |
| 几何 | 原点／基线、行距、最长混排、宽度恰好与±1px、相邻字段、背景分割线 |
| 全文 | 行页守恒、末字、显式段落、超长英文、中文禁则；无静默截断 |
| 动画 | 全部显露索引、补全、下一页、跳过、自动、取消、重入；事件只执行原次数 |
| 交互 | 首末项、空列表、全部存档槽／道具格、滚动、装备、键鼠／手柄高亮与命中 |
| 画面 | 父clip／FBO／viewport、遮挡顺序、fade、shader效果、CRT和最终倍率 |
| 变体 | JAR单独、JAR＋PAK覆盖；实际字典／脚本／背景及语言替换模式 |
| 交付 | 已验收归档／字体／profile身份一致；不把旧原型测试挪给新包 |

**完成标准不是“能显示汉字”或“测试不崩溃”，而是每个已声明显示面的全文可读、位置稳定、无笔画／字段／面板冲突、输入与事件一致。**
