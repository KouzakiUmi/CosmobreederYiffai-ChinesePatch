# 字体渲染逆向与补丁指南

> 适用版本：Cosmobreeder Yiffai `1.0.5_full`。复核日期：2026-10-21（Asia/Hong_Kong）。
>
> **这是基于原归档字节码的实现说明，不是已完成的排版补丁。** 本轮只读分析游戏与现有运行时资产；没有启动游戏/JVM、修改游戏归档、安装字体或重新打包。下文把本轮静态证据、历史实机记录和待验证建议分开。

## 1. 先看结论

1. 游戏使用**预生成位图字库**，不是在运行时用系统 TTF 绘制正文。默认文字的度量来自 [原版 FNT 快照](<font-evidence/snapshot/bbc2.fnt.txt>)，像素来自大图集中的 `bbc2` region。
2. `PRG/Yg` 是游戏绘制接口 `PRG/SN` 的实现；真正的字体对象是 `PRG/arp`。完整底层链路是 `Yg → arp → arq → arr / arp$a → arq → ars → 图形后端`。
3. **至少有三种不同的排版定位方式**：Yg 外部分行用 wrapper 步进；VSN 字幕 `jo` 每行减 16；`Id` 的逐字入口每字加 8。它们不是同一个“字体行高”。
4. 当前中文字库的 advance 为 12，而旧空格 advance 为 8。底层能按 glyph advance 绘制，但部分上层仍按字符数或固定 8 格定位。
5. 新增字形的透明 RGB 必须与 `ONE / ONE_MINUS_SRC_ALPHA` 混合兼容。旧白块不能再解释为 128×128 坐标硬限制。
6. 本轮补齐了地图居中的真实调用者、长度 helper 的动画用途、`dingbats` 消费方及字幕后处理的 8 像素周期规则。**禁止全局替换数字 8、String.length 或共享分行 helper。**

建议阅读顺序：第 3 节调用图 → 第 5–7 节底层实现 → 第 8–10 节排版与着色 → 第 12 节补丁切入点。

下一阶段设计见[文字渲染管线重写方案](<文字渲染管线重写方案.md>)：独立字库、稳定全文布局、最终CRT文字核心保护，附离线样张与可读性验收条件。

### 2.2 覆盖范围

- 保存 24 个主链类与 6 个补充类的完整反汇编；每个文本首行含 class SHA-256。
- 遍历主归档全部 class 的指定符号引用，记录 **708 条**调用/字段引用；这是定向符号检索，不是整款游戏所有逻辑的反编译或全路径运行证明。
- 重验[项目配置](<../localization/project.json#L25-L32>)登记的 6 个运行时文件，全部匹配。结果见[清单](<font-evidence/snapshot/inventory.json>)。
- 所有 PC 均为**该方法 Code 内的字节码偏移**，不是 class 文件绝对偏移，更不是 ZIP 中的偏移。混淆名、descriptor、SHA 必须一起匹配。
- 反射、JNI 和动态生成代码不在静态符号扫描的完备性承诺内；截图、GPU 和容器裁切均未在本轮验证。

## 4. 注册、资源来源与所有权

### 4.1 三款注册字体

`iF.a(Yh)V` 的实际行为：

| 注册名 | FNT / region | flip | wrapper 步进 | 附加行为 |
|---|---|---|---:|---|
| `default` | [bbc2.fnt](<font-evidence/snapshot/bbc2.fnt.txt>) / `bbc2` | false | 8，PC33 | 默认正文路径 |
| `classic` | [classic.fnt](<font-evidence/snapshot/classic.fnt.txt>) / `classic` | false | 8，PC120 | 注册前 PC110 调 `arp.a(CharSequence)`，将选定字符调为等宽、清 kerning |
| `dingbats` | [dingbats.fnt](<font-evidence/snapshot/dingbats.fnt.txt>) / `dingbats` | false | 8，PC160 | 有真实消费方，不能删除或统一改为 default |

文件内容分别见[default 定义](<font-evidence/snapshot/bbc2.fnt.txt>)、[classic 定义](<font-evidence/snapshot/classic.fnt.txt>)、[dingbats 定义](<font-evidence/snapshot/dingbats.fnt.txt>)。注册存入 `Yq` 的 map；`Yq$b.b` 持有 `arp`，`Yq$b.c` 持有整数步进，`a()`/`e()`分别返回二者。

**旧报告的“classic/dingbats 无调用方”不能继续沿用。** `Id.a(SN,Z,String,II)V` 在布尔参数为 true 时明确传 `dingbats`，false 时取 `SN.b()` 的默认名；见[实际调用](<font-evidence/callers/Id.txt#L284-L301>)。`jo` 对 `Fox` / `HardFox` 与场景布尔量选择该分支；具体剧情语义不能仅凭名字推断。classic 是否在所有实际场景可达，本轮不作否定结论。

`Yq.<init>` 仍创建 [st 字体定义](<font-evidence/snapshot/st.fnt.txt>)对应对象并写 `Yq.o`。本轮直接字段引用扫描只有该写入，没有读引用；这意味着“不是已找到的正文字体”，**不意味着可删初始化依赖**。

### 4.2 图集覆盖与坐标

两归档的 `dataq/0` 都是加密索引，键有前导 `/`：`/sprites.atlas → 5`、`/sprites.png → 6`。不要用不带 `/` 的键，也不要把槽位当跨版本永恒编号。封装及读写设施见[资源编解码器](<../cosmo_codec.py>)。

| 原始 region | JAR 坐标 | PAK 坐标 | 尺寸 |
|---|---|---|---|
| `bbc2` | `(1328,2656)` | `(1232,2512)` | `128×128` |
| `classic` | `(8,3576)` | `(8,3576)` | `512×512` |
| `dingbats` | `(528,3608)` | `(528,3608)` | `256×128` |

依据：[JAR 图集](<font-evidence/snapshot/jar-sprites.atlas.txt#L48272-L48292>)、[PAK 图集](<font-evidence/snapshot/patch-sprites.atlas.txt#L49980-L50000>)。原页尺寸 `4096×4096`，Nearest 过滤，以上 region 不旋转、offset 为零、orig 等于 size。**旧资料中的 `(1232,2512)` 是补丁页坐标，不能用于主归档。**

### 4.3 FNT 的 page 文件名不是当前像素源

注册使用的构造器是 `arp(aqX,arI,Z)`，先解析 FNT，再把传入 region 包成一个元素的数组。已有非空 region 时，不从 FNT 的 `page file=`另加载 PNG；仍会解析 page 定义和 glyph 的 page 编号。详见[构造与绑定](<font-evidence/snapshot/arp.txt#L96-L251>)。

因此：

- 只替换独立的 `bbc2.png`，并不能改变当前注册路径的像素。
- 只新增 atlas 页但不改变 `bbc2` region 的纹理归属，也不会切换字体页。
- 当前构造器只供应一个 region，新增 glyph 保持 `page=0`。多页 BMFont 支持在底层存在，不代表此注册方式已配置多页。
- 传入外部 region 时 `arp.f=false`；`dispose()`不会释放借用纹理，避免字体对象重复销毁共享图集。改变纹理供给方案时必须同时考虑生命周期，不能随意在字体销毁时释放全图集。

## 5. FNT 解析与字形数据结构

### 5.1 字段映射

`arp$a.a(aqX,Z)V`读取文本 FNT，逐 token 填写 `arp$b`。这里保留混淆字段名，方便制作精确补丁。

| `arp$b` 字段 | 含义 |
|---|---|
| `a:I` | 字符 ID |
| `b:I`, `c:I` | srcX、srcY，region 内坐标 |
| `d:I`, `e:I` | width、height |
| `f:F`, `g:F`, `h:F`, `i:F` | u、v、u2、v2 |
| `j:I` | xoffset |
| `k:I` | 转换后的 yoffset；当前 flip=false 时为 `-(height + FNT.yoffset)` |
| `l:I` | xadvance |
| `m:[[B` | 分页存储的 kerning（有符号 byte 值） |
| `n:Z` | 固定宽度标志 |
| `o:I` | page 编号 |

重要字体数据字段：`i:F=lineHeight`、`j:F=capHeight`、`k:F=ascent`、`l:F=descent`、`m:F=down`、`n:F=blankLineScale`、`o/p:F=scaleX/Y`、`q:Z=markupEnabled`、`r=glyph 表`、`s=missingGlyph`、`t:F=spaceXadvance`。

注意两个不同类的 `k` 完全不是同一概念。FNT 的 `base`参与 `ascent = base - capHeight`；当前不翻转路径的 `down = -lineHeight`。`metrics` 扩展记录存在覆盖分支，因此不能把默认推导套到任意 FNT。[解析后的度量计算](<font-evidence/snapshot/arp_a.txt#L1030-L1234>)。

### 5.2 Unicode 与缺字

- glyph 表有 128 个桶，每桶 512 项；查找 `r[ch / 512][ch & 511]`，是 UTF-16 `char`/BMP 结构，不是 128 像素图形限制。
- FNT 解析对 `id>65535`跳过；`id<=0`用于 missingGlyph。
- 布局按 `CharSequence.charAt`逐码元取字，不是按 Unicode code point 或字素簇。
- 找不到字形时，有 missingGlyph 就用它，否则跳过，不自动调用系统字体或显示问号。
- CR (`\r`)被字形收集跳过；LF (`\n`)由上层 `arr`拆 run/行处理。

[查字和缺字分支](<font-evidence/snapshot/arp_a.txt#L1579-L1653>)。当前原版与中文字库均没有 `id<=0` fallback，缺字不能靠操作系统补足；Emoji、扩展区汉字与组合字符也不能宣称自动支持。

FNT 头的 `unicode=0`在这个解析路径没有被用作“只允许 ASCII”的开关；中文解析失败应区分脚本语法与字形覆盖，不要盲改此标志。

### 5.3 当前运行时字体

[项目 FNT](<../localization/runtime/bbc2.fnt>)已复核：

| 指标 | 原版 | 当前 CJK 资产 |
|---|---:|---:|
| glyph 数 | 97 | 7489 |
| lineHeight / base | 8 / 8 | 13 / 10 |
| FNT scaleW / scaleH | 128 / 128 | 2048 / 2048 |
| ASCII / 空格 advance | 8 | 8 |
| 中文常用字、全角标点 advance | 无 | 12 |
| 常用中文字框 | 无 | 12×12，yoffset=-3 → 内部 k=-9 |

FNT 文件里的 `scaleW/H`是资源描述，不等于运行时 `scaleX/Y`。后者构造时为 1；全归档定向扫描只找到构造函数写入 `o/p`，没有普通字节码写入 `q`。[状态写入证据](<font-evidence/callers/font-state-writes.json>)支持“该静态路径 scale=1、markup 默认为 false”，但不排除反射/native 改状态，也不代表窗口最终放大倍率为 1。

## 6. 字形如何映射到图集 UV

`arp`按 `glyph.page`选择 region，再调用 `arp$a.a(Glyph,TextureRegion)`。分母来自**整个纹理实际宽高**，不是 FNT 的 scaleW/H，也不是 region 的宽高。

对于当前不旋转、不裁边 region，且 flip=false：

```text
u  = region.u + srcX / textureWidth
u2 = region.u + (srcX + width) / textureWidth
v2 = region.v + srcY / textureHeight
v  = region.v + (srcY + height) / textureHeight
```

注意 v/v2 的方向；不能只复制两个 UV 值就认为上下正确。证据：[UV 与 AtlasRegion 修正](<font-evidence/snapshot/arp_a.txt#L1266-L1495>)。

若 region 带 atlas trim offset，该方法先修正有效 src 范围，还可能修改 glyph 的 width/height/xoffset/yoffset。当前 `bbc2` offset=0，所以**没有理由为扩大字库而关闭裁剪代码**。源坐标只需落在真实 region 和纹理内。

当前打包方案把字库放到新大页底部：纹理 `4096×6144`，`bbc2` region=`(0,4096,2048,2048)`。FNT 的 glyph 坐标仍相对 `bbc2`，不能再自行加 4096。详见[实际打包逻辑](<../localization/tools/package.py#L80-L98>)。

## 7. 布局、缓存、顶点与提交

### 7.1 一次单行入口实际做什么

`Yg.a(String,int,int,String)V`取 font wrapper 后调用 `arp.a(aro,CharSequence,float,float)`；带 `aBa`颜色参数的重载先设字体颜色，绘制后恢复白色，**不是恢复任意上次颜色**。[单行与颜色入口](<font-evidence/snapshot/Yg.txt#L437-L501>)。

`arp.draw`依次：

1. `arq.b()`清旧布局/顶点计数，归还池中布局。
2. `arq.a(CharSequence,x,y)`从池获取 `arr`并计算本次布局。
3. `arq.a(aro)`按 page 将顶点交给 batch。
4. 返回本次 `arr`，但 Yg 用 `pop`丢弃返回值，未拿布局宽高回调容器。

[字体 draw 桥](<font-evidence/snapshot/arp.txt#L254-L270>)、[缓存清理和提交](<font-evidence/snapshot/arq.txt#L102-L184>)。所以此便捷调用**不是跨帧保留已排好文本的缓存 API**；也不要长期持有下一次 draw 可能归还/复用的布局对象。

### 7.2 此路径并未启用像素自动换行

`arq.a(CharSequence,FF)`明确传：start=0、end=length、targetWidth=0、align=8、wrap=false、truncate=null，见[实参](<font-evidence/snapshot/arq.txt#L747-L790>)。内部 `arr`具有 wrap/truncate 分支，但 Yg 当前这个入口不使用它们。

**显式 LF 仍生效**，因为 `arr`在 wrap 之外检查 LF；空行使用 `blankLineScale`。内部布局总高度是 `capHeight + abs(累计行位移)`，不是 `行数 × FNT.lineHeight`，更不是非透明墨迹包围盒。[LF 和高度](<font-evidence/snapshot/arr.txt#L377-L419>)；[switch 精确分支](<font-evidence/callers/switches.json>)。

颜色 markup 分支受 `arp$a.q`控制；本轮普通写入扫描没有启用它的代码。不能把历史字幕中的 `[]`现象直接解释成 libGDX 的颜色标签，或在补丁中擅自启用 markup。上层脚本、字形图案和着色器各自可能影响显示，应保留原有标记。

### 7.3 真正的字宽、顶点坐标

字形收集会生成 advance 数组：首字受 xoffset/左 padding影响；后续字间距离取 `previous.xadvance + previous.kerning(current)`再乘 scaleX；末尾宽度还考虑最后字形宽度、offset、右 padding及 fixedWidth 标志。[advance 构建](<font-evidence/snapshot/arp_a.txt#L1654-L1726>)。

因此，`sum(xadvance)`可以做提示，不能直接冒充当前 `arr.d`宽度；后者还比较 glyph 右边界与最终步进。[布局宽度计算](<font-evidence/snapshot/arr.txt#L421-L513>)。

缓存生成顶点的简化式（不含取整细节）：

```text
x = drawX + run.x + 累积advance + glyph.xoffset * scaleX
y = drawY + font.ascent + run.y + glyph.yoffset_internal * scaleY
w = glyph.width  * scaleX
h = glyph.height * scaleY
```

构造链启用整数位置；`arq`对 x/y/w/h做 `Math.round`。每字写四个顶点、共 20 个 float 槽，每顶点是 `(x,y,packedColor,u,v)`；按 glyph.page 放入独立数组。[坐标与顶点](<font-evidence/snapshot/arq.txt#L532-L745>)、[ascent 桥](<font-evidence/snapshot/arq.txt#L792-L803>)。

这解释了为什么修改 `base`、`yoffset`、行步进会产生不同影响。不能把 FNT.yoffset直接当成最终屏幕坐标。

`ars`接收纹理和 float 数组，必要时刷新批次；flush 按 `floatCount/20`得到四边形数，每个使用 6 个索引提交。[flush](<font-evidence/snapshot/ars.txt#L1293-L1390>)。是否换纹理/容量刷新属于批次行为，不改变 FNT 的字符语义。

## 8. 上层排版：不能只修一个数字

### 8.1 Yg 外部分行

入口：`Yg.a(I,I,String,amq,I,String)V`。`amq.a()`的返回值 N 被交给 `amr$e.a(String,N)`，经 `aDJ.e`构造 `aDI$a`，按 **UTF-16 码元配额**切块：

```text
对 N > 0：
  for c = 0; c < s.length; c += N:
      block = s.substring(c, min(c + N, s.length))

第 i 个块：
  drawX = suppliedX
  drawY = suppliedY + 1 + (wrapper.e() + extraSpacing) * i + 8
```

[分行调用](<font-evidence/snapshot/Yg.txt#L507-L539>)、[实际切片迭代器](<font-evidence/snapshot/aDI_a.txt>)、[行定位](<font-evidence/snapshot/Yg.txt#L749-L780>)。

空格、换行和标记字符都计入这一层的 N；这里不找词边界、不读实际 glyph advance。块内 LF 再由 `arr`处理，所以外层块数不必等于画面行数。N<=0 是待排除的调用前提，补丁不要主动制造非正配额。

只改 FNT.lineHeight=13，不会改变 wrapper.e()=8。只把 default 的注册步进改成 13，也不会修横向配额、容器高度或底下两类入口。

### 8.2 VSN 字幕是另一条定位链：16 步进

`jl.a(SN,anh,ZJ,amq,I,I,Z)`读取 `amq.a()`为配额，并将同一 amq 对象传给 `jo`。[构造关系](<font-evidence/snapshot/jl.txt#L242-L260>)。

`jo`接收动画字符串的“可见前缀＋等长ASCII空格后缀”掩码串，再调用同一个固定切块 helper；它不是把String截短到当前可见长度。其逐行回调是：

```text
lineY = jo.f - 16 * lineIndex
Id.drawText(SN, useDingbats, line, jo.e, lineY)
```

[VSN 逐行回调](<font-evidence/snapshot/jo.txt#L80-L162>)最终走 **Yg 单行重载**，不是 Yg 的 wrapper 多行重载。因此把 wrapper 8→13，不会把这里的 16→13，也不能用片头字幕成功证明普通 UI 多行已经修好。

`jo`还把结束提示的横坐标设为 `jo.e + jo.g.a()*8 + 2`，并以 `jo.f-40`推导纵坐标，再绘制 `WhiteFill`。在 jl 这个构造入口，配额快照和 amq来自同次传递；除非另证 amq 稳定，不把“构造时值”和“后来再读的值”视为永远相同。汉字变宽以后，这个固定 8 的提示位置同样需要检查。

### 8.3 Id 逐字绘制：固定横向 8 格

`Id.a(SN,String,II)`以及带颜色重载遍历字符，将 x 从传入值起每次加 8，然后**逐个字符调用 SN 的文字入口**。[入口](<font-evidence/callers/Id.txt#L243-L278>)、[步进和单字调用](<font-evidence/callers/Id.txt#L303-L367>)。

单字宽度即使为 12，下一个字的 origin仍可能只移 8；这与“完整字符串一次交给 arp”的 advance 路径不同。当前尚未逐个确认这两个入口的所有实际界面，但实现本身已证，后续需把它们作为独立验收项。

## 9. 居中辅助、真实调用者与共享 helper 风险

`Yg.a(String,int,String)I`并不用 `arr`测宽，而是：

```text
estimatedWidth = String.length() * font.spaceXadvance
x = ceil((integer(containerWidth/2) - estimatedWidth/2) / 8) * 8 - 1
```

[完整计算](<font-evidence/snapshot/Yg.txt#L391-L431>)。当前空格 advance8、中文 advance12，估宽存在静态失配；具体可见偏差还受首尾 offset、8 格舍入、容器和文本影响。

### 本轮已找到实际调用者

`Lx.a(SN,Z)V`的 PC720 通过 **接口 SN**调用居中辅助，容器宽传 256；PC747 用结果作为同一字符串的 x 绘制。附近分支通过 `navmap.current_location`构造显示字符串，并在非空列表中按时间选择内容。[地图调用现场](<font-evidence/callers/Lx.txt#L862-L924>)。

这补上了[旧换行分析](<../localization/reports/planning/cjk-wrap-analysis-001.md#L59-L71>)的“调用者未知”：只查 `invokevirtual Yg`会漏掉 `invokeinterface SN`。这是静态调用闭环，不是地图画面已验收。

### 为什么不能全局替换 String.length

同一个 `amr$e.d(String)I`还被：

- `amn.a(D,Z)I`用于打字机结束位置，随后 `amw.a(String,I)`生成可见前缀加空格后缀、总长度不变的掩码串；[动画字符串](<font-evidence/callers/amn.txt#L41-L109>)。
- `amo.a(amn,D,Z,azB)`比较当前前缀与全文的长度，生成是否显示完毕的布尔值；[完成判断](<font-evidence/callers/amo.txt#L34-L73>)。

它们需要字符串索引/长度，而不是像素宽。把共享 helper 改成测宽会改变前缀截取和播放完成时机。应该在**已确认的显示入口**新增/替换局部测宽逻辑，保留动画与字符串工具原语义。

另有 `amw`的按空格、`<p>`、管道符预处理/排版方法，见[相关实现](<font-evidence/callers/amw.txt#L84-L318>)。本指南不把 `Yg`和 `jo`两处固定切块推广成“全游戏只有这一种排版算法”。

## 10. 混合与终端着色器

### 10.1 为什么透明白会形成实心字块

`Yg.<init>` PC43–47 设置 `ars.a(1,771)`；二参数方法把同一对参数传给 RGB/Alpha 四参数版本，flush 时提交给后端。[设置](<font-evidence/snapshot/Yg.txt#L791-L818>)、[参数传递](<font-evidence/snapshot/ars.txt#L1416-L1457>)。

对应 `ONE / ONE_MINUS_SRC_ALPHA`时，RGB合成式为：

```text
out.rgb = src.rgb + dst.rgb * (1 - src.a)
```

若源像素是 `(255,255,255,0)`，Alpha为零并不让源 RGB自动消失。原构建器曾创建这种透明白画布；[构建器证据](<../build_cjkfont.py#L113-L139>)。历史修复把新字库 RGB预乘 Alpha，二值 Alpha时就是把透明像素变为全零。

`jl`明确将字幕中间画面交给 `vsn_term_shade`，并设置 `texture_size=(256,224)`，不是从一个未使用的 shader 名称猜测。[使用现场](<font-evidence/snapshot/jl.txt#L906-L963>)。

[字幕 shader](<font-evidence/snapshot/shaders_vsn_term_shade.frag.txt#L18-L48>)遇到红通道>0就输出不透明金色内部色；透明白污染中间画面后，会把整块字框着色。历史实机记录与截图见[接手结论](<../research/接手研究结论.md#L18-L57>)和[截图](<../research/intro-00.png>)。本轮只复核其代码依据，没有重新拍摄。

**不建议通过全局改混合模式绕过字库问题**，因为共享图集、已有 shader 和其他美术也依赖现有行为。

### 10.2 本轮补充：8 像素周期描边不是行高

两个终端 shader 都有：

```glsl
int my = int(mod(py + 1.0, 8.0));
if (my != 0) {
    // 才采样另一个纵向相邻像素
}
```

这是按中间画面的 y 坐标控制邻域采样，不是 glyph 裁剪或 wrapper 行距。[字幕版](<font-evidence/snapshot/shaders_vsn_term_shade.frag.txt#L32-L47>)、[普通终端版](<font-evidence/snapshot/shaders_cosmo_term_shade.frag.txt#L31-L47>)。

改变到 12/13 高字形或新的行 origin后，其描边可能不再与旧 8 格边界一致；**实际视觉影响待验证**，不能未经对照就把 shader 中 8 改成 13。

两 shader 也不能互换：普通终端版先检查 Alpha零并用黑色背景；字幕版无该首判断，描边之外输出透明。`Id`使用普通终端版时同样设置 `texture_size=(256,224)`。[普通终端使用现场](<font-evidence/callers/Id.txt#L58-L114>)。这里的 256×224是后处理画面尺度，不是大图集尺寸。

## 11. 脚本解析、字库和打包是三道不同门槛

原 `afH`共享正文规则主要接受 ASCII。现有运行时补丁重定向 `afH.n(auN)` PC52 的三字节调用到 `cosmoloc.CjkText.letter`，只增加当前字体覆盖的非 ASCII BMP字符，不全局放开标识符或脚本结构。

本轮核验了[运行时补丁指纹](<font-evidence/snapshot/inventory.json>)，没有重跑解析回归。机制、67份有效 VSN历史回归和边界见[既有解析研究](<../research/接手研究结论.md#L59-L115>)。换字库时，要同步检查正文白名单；“glyph 存在”和“语法接受”是两回事。

当前[打包入口](<../localization/tools/package.py#L101-L147>)：

- 对两个资源归档分别扩大图集、更新 `bbc2` region，保持原美术区域；主归档另外替换字体定义与正文补丁 class。
- 使用[已预乘的运行时字库](<../localization/runtime/cjkfont.png>)，不能直接拿旧构建器的未经修正输出替代。
- **没有自动安装 wrapper 13、地图测宽或 VSN行距补丁。** 已存在的 default13 overlay只是候选实验，不是当前正式打包能力。
- class 常量池修改按精确索引，保留其余字节码；混淆类有大小写冲突，后续仍应在 ZIP/JAR内按精确 entry 操作。

当前 4096×6144 RGBA页的单份未压缩像素约96 MiB，原页约64 MiB；这只是 CPU/GPU单份基准算术，不是实测总显存。纹理上限、重复驻留、其他固定4096采样特效仍需实机检查。

## 12. 后续补丁切入点与验收矩阵

以下是按现有事实提出的候选，不代表本轮已实施或验证。

| 优先项 | 精确切入点 | 能解决 / 不能解决 | 最低验证 |
|---|---|---|---|
| 字库/像素 | FNT + 两归档 `bbc2` region/大页 | 增加字形、消除透明RGB污染；不修上层定位 | glyph覆盖、page=0、透明RGB、UV边界、英文原字形不变 |
| 普通外部分行 | `iF.a(Yh)V` PC33 default wrapper参数 | 调整 Yg 多行步进；不影响 jo的16或Id逐字8 | 英中1/2/3行、extraSpacing、首行/末行、命中区和容器 |
| 横向配额 | 已确认 UI入口的 N/局部分行 | 让配额与实际宽度协调；不改共享 aDJ/amr工具 | 中英混排、空格、LF、空行、标记、边界长串 |
| 地图居中 | `Lx.a(SN,Z)V` PC720 或专用字体测宽入口 | 替代字符数估宽；须保留既有8格定位是否必要的对照 | 256宽地图标题/提示，英文回归，左右边界 |
| VSN排版 | `jo`行定位、结束提示位置、`Id`字体选择 | 独立处理16步进和8格提示；不能借wrapper补丁代替 | 多行字幕、打字机、Fox/HardFox分支、结束提示、长译文 |
| 固定格逐字入口 | `Id.a(SN,String,II)`及颜色重载 | 处理每字8格与12宽glyph失配 | 定位实际消费者；相邻字间距/颜色/动画对照 |
| 描边 | 两个终端 shader 的8周期采样 | 处理新行origin与描边边界；不是增加字形的先决条件 | 不同y偏移、中文笔画、透明背景、普通终端对照 |

测宽实现应以目标归档实际 `arr`/glyph 逻辑为依据，不能把新版 libGDX API示例直接编入未知版本游戏。新增布局对象若复用现有池，需明确借用期限；不要把 arp.draw返回、随后会被池复用的临时布局长期缓存；Yg本身丢弃该返回值。

验证顺序建议：指纹与精确指令断言 → 新候选归档的差分白名单 → JVM校验 → 实际调用 → 场景截图/GPU回归。**JVM verifier通过不等于字体注册执行，更不等于画面排版通过。** 既有[default13 JVM结果](<../localization/reports/planning/cjk-jvm-verify-002/RESULT.md>)仅支持其记录的验证边界。

## 14. 文档、许可与尚未覆盖事项

### 外部文档核验

已通过 Context7查询 libGDX官方 Wiki 的外部 TextureRegion构造和缓存/颜色概念，以及批次混合/FrameBuffer概念。来源：[位图字体](<https://github.com/libgdx/libgdx.github.io/blob/dev/wiki/graphics/2d/fonts/bitmap-fonts.md>)、[外部纹理构造示例](<https://github.com/libgdx/libgdx.github.io/blob/dev/wiki/graphics/2d/fonts/distance-field-fonts.md>)、[颜色 markup](<https://github.com/libgdx/libgdx.github.io/blob/dev/wiki/graphics/2d/fonts/color-markup-language.md>)、[混合与遮罩](<https://github.com/libgdx/libgdx.github.io/blob/dev/wiki/graphics/2d/masking.md>)。

**精确 libGDX版本仍未知，查询也没有完整覆盖本游戏的预乘混合链和缓存内部实现。** 外部资料只作概念对照；本指南的方法签名、字段、公式和启用状态以本地字节码/着色器为证，不声称完成版本兼容性认证。没有据新版契约修改游戏实现。

### 字体许可

本轮使用既有资产，没有选择、下载或安装新字体。[NOTICE](<../localization/runtime/NOTICE.txt>)记录新增CJK来自 Fusion Pixel 12px Mono zh-Hans Regular `2026.09.25`，附[OFL 1.1](<../localization/runtime/LICENSE-FusionPixel-OFL.txt>)；原TTF不在项目内。组合字库还含原游戏ASCII像素，OFL不能替代原游戏的分发授权。这里核验的是项目许可材料和指纹，不是再次核验系统TTF安装状态。

### 仍需后续验证

- 所有 UI容器的实际宽高、滚动分页、选择框、鼠标/手柄命中区。
- dingbats分支的中文语义和覆盖需求，classic实际场景。

- 本轮没有重跑历史解析回归、JVM候选实验或实机截图；没有把静态分析称为全游戏验收。

旧报告保留历史实验，但后续字体实现工作应从本指南和对应证据进入，不再从“128硬上限”“Yg是全部上层文字唯一消费者”“只改lineHeight就完成排版”等推断出发。
