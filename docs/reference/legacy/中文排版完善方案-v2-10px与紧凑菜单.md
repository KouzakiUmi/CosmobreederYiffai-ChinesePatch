# 中文排版完善方案 v2：10px下限与紧凑菜单重排

> 依据：2026-10-24用户实机反馈、当日r21构建/安装核验记录、现有全游戏静态研究；2026-10-25补充补丁设计约束。
> 前一设计轮仅定向复读打包入口与DS静态证据，未实现补丁；2026-10-25后续已进入P0/P1源码及隔离候选实施，实证校正与验收边界见第11节。原安装、正式译文与存档未修改，未以离线通过冒充实机验收。
> 承接[全游戏总方案](<全游戏中文排版研究与补丁总方案.md>)；不重新进行全量逆向，也不把重写整个渲染引擎作为前置。

## 1. 结论：中文不降回8px，让控件适配10px

本轮采用以下约束：

- **必读中文以至少10px可读字形为底线。** 这是用户对当前字体/显示效果的反馈，不是“任何10px字体都必然清晰”的普适结论。
- **8px可以保留给原ASCII数字、时间、等级、键位和图标**，不能作为中文正文/名称的最终可读方案。
- 8px坐标网格、字形宽高、glyph advance、行步进、字段宽度是五个独立量。原网格可以保留，中文绘制与控件布局不再依赖它来推算容量。
- 小菜单放不下时，优先局部调整行距/列宽、减少同时可见行数、复用已有详情区与翻页能力。保留完整数据，不靠改短译文或缩字掩盖溢出。

> 🧠 **From Hindsight memory (开场资源隔离汉化验证补丁)** — 历史研究已指出固定字符配额与中文实际字宽不一致，装载和缺字检查通过不等于排版通过。以下结论重新以当前r21文件核实，不沿用旧版字体状态。

## 2. r21冻结现场：问题不是“仍没换字体”，而是只换了字体

证据见[本轮只读核验](<layout-refinement-20261024/evidence.json>)及[复算脚本](<layout-refinement-20261024/inspect_current.py>)。

| 项目 | 本轮观察 |
|---|---|
| 已安装归档 | 主JAR和官方PAK均与[当前r21-images构建清单](<../localization/builds/final-8146-r21-images/package-manifest.json>)匹配 |
| 默认字体 | [bbc2定义](<../localization/runtime/bbc2.fnt#L1-L12>)为size10、lineHeight14；抽查中文字框10×10、advance10；ASCII空格仍advance8 |
| classic字体 | [classic定义](<../localization/runtime/classic.fnt#L1-L10>)仍为size8、lineHeight8；抽查中文advance8 |
| 关键逻辑 | Id、It、Yg、Yq$b、iF、jo、JR/JQ、Kl/Kk、Nb/Na、amw、LX/LY/Mb/Kr/Eu/Ew/LJ/LK共21个class，与原归档完全相同 |
| 打包路径 | r21记录为10px默认字库＋8px classic，且未含布局类改造；[现有打包入口](<../localization/tools/package.py>)后续已新增显式布局bundle接入，第11节记录其边界 |
| 安装器版本 | [安装清单](<../localization/packaging/manifest.json>)仍标1.5，载荷SHA不等于当前r21；不能用安装器文件名证明装的是同一测试包 |
| 现有截图 | [无线电画面](<../localization/work/fontprobe/shot.png>)可见正文冲出右边；截图没有可靠的构建身份绑定，本轮不据它倒推精确字号或菜单clip |

因此，当前症状符合两条同时存在的失配：

1. **横向：** 字符配额/逐字步进仍按旧规则，实际中文已经10px宽。
2. **纵向和字段：** 原8px行位、64px姓名字段、固定图标/邻列没有同步扩大。

并且default升到10px不覆盖仍使用classic的菜单；反过来，存档/道具也不能统一归因于classic，因为其中存在default与Id逐字路径。

[默认字体生成脚本](<../localization/tools/make-bbc2-cjk.py#L2-L15>)的“中文必须等于8px”是旧网格兼容办法，不是引擎不能绘10px的限制。该脚本当前仍固定CELL=8、覆盖通用bbc2定义，而打包器固定选择10px PNG；后续若盲目重跑，存在定义/图集版本配错风险。本轮不执行它。

## 3. 把“遮挡”分成四种，不能只调字号或绘制顺序

| 类型 | 可观察特征 | 修复对象 |
|---|---|---|
| 字形互相压住 | 汉字原点间隔仍8，字框宽10，邻字有约2px重叠风险 | 逐字入口的advance/累计位置；不是只改FNT |
| 相邻字段相撞 | 名字、图标、等级、日期分别画，却使用固定+64/+80偏移 | 字段矩形和列锚点 |
| 上下行相撞 | 字框/描边高度大于原行步进，上一行/下一行覆盖 | 控件行高、基线和列表排布 |
| 被背景或父裁剪吃掉 | 字形坐标正确但边缘被切，或后画背景盖住正文 | 父clip/FBO/viewport、背景与正文合成顺序 |

实现时给诊断模式显示：容器边界、各字段矩形、glyph墨迹/效果边界、绘制原点、当前font/profile与clip。这个叠框是取证工具，不是发行画面。

**禁止用“最后再画文字”统一解决遮挡。** 若根因是两列几何重叠，换顺序只是让另一列被盖；若根因是clip，最后画也未必可见。更不能绕过原场景遮挡/fade，把文字无条件铺到最上层。

## 4. 字体与行高策略：10px紧凑、12px正文、8px数值

| 显示角色 | 初始候选 | 行步进候选 | 用法 |
|---|---:|---:|---|
| 紧凑中文标签/名字 | 10px | **14px优先** | 存档、道具列表、菜单、说明标题 |
| 连续阅读正文 | 先复用当前10px；空间允许时12px | 10px试14–16；12px试16 | 无线电、DS、VSN、道具详情 |
| 数字/时间/键位 | 原8px ASCII | 从属所在行盒 | 与中文混排时仍用原数字字形，但共用校准后的基线 |
| 语义符号字体 | 保留角色 | 单独校准 | 不把dingbats或其他符号统一替换成普通中文 |

表中行步进是**待画面验收的profile初值**，不是已测得的最优值。实际行盒应容纳同一行所有字体的ascent/descent、offset及描边。10px字框加上下效果边距可能需要12px以上；当前FNT lineHeight14可作起点，但不自动约束外层布局。

关键实现规则：

- 不允许“字形画10px、advance谎报8px”；也不能只加大advance而保留邻字段旧位置。
- 不把全局`It.a/b`的乘8改成10；原场景/图标/网格仍需要原坐标。只改文字控件的局部行列计算。
- default与classic各自提供已核验的中文角色；未适配场景保持原路径，不为修两个菜单同时扩大所有文字。
- 同一句已确定profile后不按显露进度或临时长度自动缩放，以免打字时跳动。
- 现有10/12px资源可作为试验输入；新字库生成器、覆盖字符集、具体字体来源/许可必须在实施时核验，不仅改`info size`冒称换成可读字号。

## 5. 自动换行：以实际可用像素宽度为输入

### 5.1 最小核心契约

```text
layout(fullDisplayText, actualFontMetrics, contentRect, breakPolicy)
  → lines/pages + glyphOrigins + sourceIndexMap + bounds

draw(plan, originalRevealIndex)
  → 只显露已确定位置的字形/行前缀，不再次换行
```

内容宽度取实际控件内宽减左右padding、效果边距以及独立图标/字段占位，不把全屏256或历史240预算直接传给所有文字。

例如旧20格×8≈160px的正文，如果实际安全内宽确认为160px，均匀10px汉字理论上只有16个advance，12px则13个；224px约22个10px字。**这只是量级说明，不把16/22硬编码成所有场景的字数上限。** 混排、offset、kerning、标点、描边和变量都要按实际字形度量计算。

### 5.2 换行和动画必须同时更换

1. 保留源身份、控制标记、变量与字体角色，先取得最终显示文本。
2. 中文按合法字符边界找断点，处理行首禁用标点/行尾开括号、英文词组和`……`；不执行旧英文长词追加连字符的规则。
3. 完整文本一次排好；原显露索引映射到固定行计划。不得把未显露中文替成8px空格后每帧重新测宽。
4. 新行循环独立控制行数。只替换旧循环最后的draw不能新增行。
5. 超高时交给场景自己的显示页/滚动策略；正文不得用省略号静默截断。

[DS补核](<full-layout-study-20261023/ds-pipeline-closure.md>)已证明：常规/窄/商店正文有20×3、12×3、28×3三套逻辑配额；三参amw按`<p>`，四参按`|`。显示层必须区分这些语义，不全局改共享helper或直接替换所有字符上限。

### 5.3 补丁边界：共享排版核心，场景适配器接管消费链

建议仅引入三层职责，不另建一套游戏UI框架：

| 层 | 输入/输出 | 禁止承担的职责 |
|---|---|---|
| 字体度量与纯布局核心 | 最终显示文本、角色度量、可用矩形、断行策略 → 不可变LayoutPlan | 不读取剧情状态、不响应按键、不执行交易/存档 |
| 场景适配器 | 提取最终文本、原索引及容器；维护显示页和列表视口；调用核心 | 不改正式译文、名字存储规则或共享网格 |
| 原渲染/输入桥接 | 按plan绘制；将原显露进度和输入路由到当前显示页/可见项 | 不每帧重新换行、不重复触发原逻辑事件 |

- **补丁定位精确到原class SHA＋方法descriptor＋调用点特征。** 不以混淆短类名或“第几个常量8”作为唯一匹配依据。任一目标不匹配，停止该候选构建并报告，不生成部分成功的发行包。
- **只接管登记过的文字路径。** 不整体替换Id、amw、It的所有调用；如果必须在共享入口桥接，应显式传入场景profile，未登记调用保持原行为。已登记中文路径缺profile不能静默退回8px或旧字符配额，而应阻断该候选验收。
- **生产端与消费端成对切换。** DS若改为像素分页，还必须移除对应消费点的20/12/28字符二次切块及空格填充依赖；不能把变长行重新串成旧定长字符串，再让原绘制循环拆开。
- **P1先闭合一条正文链。** 从VSN开场入口或JR/JQ常规DS中择一，完成全文、动画、溢出和输入验收后再扩展其余正文支路；存档与道具适配器复用核心，但分别验收。不要第一轮同时改完所有DS支路。

### 5.4 LayoutPlan、索引与缓存的最低约束

在5.1契约基础上，plan至少记录：场景/文本身份、最终显示文本修订、font与profile版本、contentRect、逻辑段落→显示页→显示行、字形原点及效果bounds、显示单元到原显露区间的映射、溢出原因。换行/分页不回写原文。

1. **最终变换后测量。** [DS补核的页后变换与大写化证据](<full-layout-study-20261023/ds-pipeline-closure.md#L93-L105>)表明不能只缓存parser原文。先确认该入口变换的实际顺序；无法消除页后变换时，将原逻辑页作为边界，在变换后生成其显示子页，保留原actor/expression和事件归属，不假定变换与分页可交换。
2. **索引单位显式标明。** 原索引若按UTF-16码元推进，桥接层保留其单位；排版不能在代理对、组合序列或控制标记内部断开。一个源区间对应多个显示单元时，采用固定的区间映射与显露策略，不把显示字形序号直接当原索引。
3. **动态变量采用明确生命周期。** 优先沿用原页开始时已确定的最终值；若原逻辑允许页内变化，只在实际文本/度量/矩形修订时重建plan，并定义进度迁移，不因每帧调用而重建。不能为了稳定排版冻结原本应实时变化的数据。
4. **缓存键覆盖全部布局输入。** 包含最终文本、字体度量版本、profile、矩形、断行策略及影响布局的变量版本；显露进度不进入键。仅限制大小并随场景/字体资源销毁释放，不跨存档或跨字体复用陈旧plan。
5. **异常也必须终止并显式报告。** 单个显示单元宽于容器时返回overflow，不进入零进展换行循环；未断开的超长英文标识可在合法显示单元边界拆行但不凭空加连字符。禁则无法同时满足时使用登记的退让规则并记录，不丢字符、不缩到8px。

### 5.5 无线电框的空间优化

现有JQ正文相对原点**右移72px**，说话者名占独立区域；[当前无线电截图](<../localization/work/fontprobe/shot.png>)也显示名字与正文同一横带。

首选先在原正文宽度内正确换行。若阅读容量仍不足，再在**同一文字框内部**把说话者名单独放到首行、正文从下一行使用全宽，减少左侧长期空占；不先扩大整个逻辑分辨率。

设名字布局占原可用宽中的72px，重排后可以回收这部分宽度，但会多占一行高度；是否增加总容量必须对真实宽高计算，不能只看到变宽就认为一定更优。自动字幕保持原时序；交互DS可以沿用原翻页动作驱动新增显示页，最后一页完成前不发出逻辑节点完成事件。

**自动字幕不能直接套交互分页。** 固定时长内容先验证是否可在原容器或框内重排后完整常显；仍超高则记录为阻塞样本，不自动延时、不快速轮播让玩家来不及读，也不静默截尾。需要改变播放时长或交互时再单独确定产品策略。

**交互DS使用两级页状态。** 原逻辑页持有若干显示子页；原有“补全打字”“确认下一页”“跳过/自动播放”动作逐项映射，禁止默认一个按键同时完成补全与跨页。进入下一个显示子页不重放角色表情、音效或交易副作用；仅末子页满足原完成条件后，推进原逻辑页一次。取消、返回、重入的状态恢复也要明确，不能只覆盖顺序确认。

## 6. 存档菜单：保留数据，改成显式字段＋更高的槽位行盒

### 6.1 为什么10px必需改字段

已证的[原槽位/名字实现](<full-layout-study-20261023/text-systems/worker2-ui-dict-map-name/report.md#L37-L97>)包含：名字截断/补齐8码元、Id固定8步进、性别图标+64、邻字段+80。

- 若仍以8步进画10字框：相邻汉字会挤压。
- 若改为正确10步进，8个全宽汉字约需80px，已大于旧64px姓名区；**邻列必须移动或分行**。
- 这不是要求把8字名字改成6字，更不是修改存档内容。逻辑名字长度与显示矩形分开。

### 6.2 设计初稿：两行槽位预算（实施已按第11节校正）

```text
第一行：名字（10px中文）   性别图标   等级（8px数字）   时间（8px数字）
第二行：地点/状态（10px中文，可用余宽）         次数/完成度（8px数字）
```

槽位内第一/第二行基线先试14px间距，组间留出间隔；**28–30px槽位高**为原型候选，不是当前已量值。原实现已有两行显示，优先改变两行之间和槽位之间的几何，不另做全新界面。

字段从数据对象直接取值，取消“拼名字＋补空格＋数字＋分隔串”的整体等宽字符串。所有字段共享一份SlotLayout：文字、图标、选中底板、光标、鼠标矩形和滚动位置都读它。

一个仅供原型比较的224px内容区预算：

```text
姓名84 + 间隔4 + 图标8 + 间隔8 + 等级48 + 间隔8 + 时间64 = 224
```

84px姓名槽可给8个10px汉字的80px advance留下少量边距；实际墨迹/描边仍须测量。时间超过预算、ASCII特殊字符越界或邻列更复杂时转第二行重新分配，不靠裁切通过。该预算不是现有菜单真实宽度证明，也不证明原有全部字段已经容纳。

**确定性后备：三行卡片。** 若两个行盒无法完整容纳原字段，姓名＋性别单独占第一行，原两行元信息重新定位到第二/第三行。以3个14px行盒＋4px组间隔计，槽高草案46px。字段集合必须与原数据展示逐项对照，不能遗漏等级、次数、日期或完成度来满足两行。由菜单profile统一选择两行或三行，不随选中项或名字长短逐帧改变槽高。

若固定槽位总高放不下全部槽：减少**同时可见**槽位并接通原选择/滚动逻辑，保持所有存档可选；不是减少可保存槽位数量。若原界面没有滚动能力，实施需显式补对应翻页，而不能把被挤出屏幕的槽位当不存在。

**列表视口统一契约（存档与道具共用）：** 选择状态保存原数据项身份/索引，不保存“屏幕第几行”。单一布局结果同时输出可见项、滚动偏移、文字矩形、选中底板与命中矩形；空列表、首末项、连续按住、原有循环选择、鼠标/手柄切换分别回归。排序、过滤或返回菜单后，以原规则恢复选择并保证选中项可见；部分露出的行不能形成不可见却可确认的目标。可见行数公式必须扣除标题、padding、页码/滚动提示占位，非正可用高度直接报告profile不可用。

## 7. 道具菜单：保留原选择结构＋详情，降低信息密度

> 以下名称/数量文字列表是设计阶段的假设模型，不是已证主道具页结构；实施确认主道具页是图标网格，第11节与实施证据优先。

### 7.1 文字列表假设下的最小重排

- 名称与数量拆字段；图标单独占位。中文名10px，数量沿用8px数字并右对齐。
- 列表行步进先试14px；按`floor(列表内容高 / 行步进)`重算可见行数，并同步选择框/命中区/滚动边界。
- 右侧或现有详情区顶部显示选中道具的**完整名称**，可占两行；其下说明按像素换行/分页。
- 非选中列表的过长名称可做可见摘要，但前提是选中后能看到完整名称与说明、相似名字可区分。不能只省略后缀而失去关键道具差别。
- 不修改正式译文来迁就窄列，也不对全库加入手工空格/换行。

示例约束：若左列实际内宽116px，图标16、两侧间隔共8、数量24，则名称仅余68px。这意味着即使10px也只有约6个汉字的advance预算，不能承诺原两栏列表全部名字完整常显。正确选择是复用详情区、局部扩大名称列或减少次要常显字段，而不是回到8px。

### 7.2 按真实消费路径分别登记，不按短类名猜场景

主道具页经Le/Lc/Ld图标网格与Lg/Lb标题说明绘制；Kr实际属于结局演出，Eu/Ew属于繁育支路，不能作为主道具列表直接改写。既有研究中的[消费点自行切两块、相邻基线8px](<full-layout-study-20261023/hud-and-assets-report.md#L15-L44>)仍提示应按**选择项、标题、说明块、状态块**分别登记profile，但场景归属以[本轮主道具页证据](<../localization/layout/research/item-menu-evidence.md>)为准。只改FNT lineHeight不能消除消费端定长二次切块。

### 7.3 备选但不优先：全宽名称列表

如果左列重排后仍无法清楚区分长名称，可将名称列表改为全宽，把现有详情移到下半区或选中详情页。这会改变更多背景框与导航，因此作为第二级方案；先验证保留现有双栏是否已经满足阅读，不为修排版一开始就重写整个道具界面。

## 8. 背景、裁剪、顺序必须跟控件一起改

- 存档/道具标题与分栏可能烘焙在背景图中。若只是文字槽位内部重排可先不动背景；若跨越原分栏，则背景线框与文案也要同步。
- 文字换行前取得实际contentRect；绘制时使用同一矩形裁剪。**裁剪只是防止破坏邻区，不能作为隐藏未读正文的修复。**
- 检查父FBO/viewport/clip、嵌套平移和控件缩放；不要把窗口截图像素当内部逻辑像素。
- 推荐控件内顺序为背景→选中底板→图标/文字→光标/提示，但需服从原场景合成。最终场景遮挡/CRT仍在原顺序执行。
- 全部几何以逻辑像素为单位。增大窗口倍率只把旧溢出一起放大，不增加文本框的逻辑容量。

## 9. 增量实施路线：沿当前构建，不先更换交付架构

当前实际使用的是重建JAR/PAK与安装器，不是早期三文件agent原型。因此这次先把布局class改造集成到现有[打包入口](<../localization/tools/package.py#L207-L225>)；三文件旁挂、独立纹理和CRT笔画保护仍可后续做，**不作为修复现有排版的前置大工程**。

### P0：冻结可复现样本与资产组合

- 固定r21输入及本轮SHA，不修改正在测试的包。
- 字体以一套manifest绑定FNT、PNG、字集、基线与字体角色，不再用“可变bbc2定义＋固定10px PNG”的隐式组合。
- 生成脚本参数化输出独立命名版本；避免旧8px生成脚本覆盖通用字体定义后被当10px打包。
- 每张测试截图绑定构建SHA、font/profile、界面/节点、显露阶段、窗口倍率；对齐安装器manifest与实际测试包，避免重复测试旧载荷。

### P1：先修一个正文入口和两个紧凑菜单，验证设计闭环

统一核心、分入口闭环：先择一正文链完成像素换行与动画/事件桥接，再验收存档槽字段重排、道具列表/详情重排。固定紧凑10px，先证明完整、稳定、无碰撞，再比较正文是否切换12px。P1不要求同时接管全部VSN/DS入口。

### P2：扩展到所有已知入口

复用[61类覆盖台账](<full-layout-study-20261023/coverage-ledger.json>)，逐类替换字符配额、独立逐字和字符数居中。旧全游戏研究继续作为清单，不重新扫整个归档；每新增profile同步几何、交互和字体角色。

### P3：再调画质与交付

几何正确后才调字形边缘、CRT和低倍率可读性；最后重新准备安装器payload、校验载荷SHA和两资源版本。不能拿“有字形、无崩溃、静态QA为0”替代画面验收。

### 9.1 构建原子性与回退单位

- 在现有打包器内增加显式布局补丁阶段，列清新增helper与目标class；与当前UTF-8常量替换共用一份替换表并约定次序，避免后一步从原归档重读而覆盖前一步成果。同一class多项修改最终只输出一个合成结果。
- 字体manifest至少绑定角色、FNT/PNG各自SHA、字集、基线/advance配置与许可文件；布局manifest绑定目标原class SHA、输出class SHA、profile版本、字体manifest SHA和归档资源位置。两者作为一组候选，不允许只回退FNT或class之一。
- 构建门禁检查：目标匹配唯一、helper齐全、字库缺字/图集边界、实际归档内FNT/PNG配对、SFW/NSFW实际资源读取路径。门禁失败保留诊断但不标为可安装产物；ZIP完整性通过不等于这些检查通过。
- P0先定义可重复的构建输入与变更清单，不承诺加密归档每次字节相同；当前打包器使用随机加密参数，最终构建以实际产物SHA绑定截图和安装器。
- 新候选输出到独立目录，保留r21基线。回退以完整归档/匹配字体与布局组合为单位；回退到r21只表示恢复旧状态，不表示旧排版已通过。安装器在候选验收后再刷新payload及manifest，不在设计阶段触碰原安装。

### 9.2 分层验证与推进门槛

| 门槛 | 必须验证 | 不能替代的下一层 |
|---|---|---|
| G0 输入冻结 | 原class身份、字体配对、profile矩形来源、字段清单 | 未测矩形不得写成实测容量 |
| G1 纯布局 | 混排/禁则/变量、宽度恰好及±1px、单元超宽、显露映射、页高边界；相同输入产生相同plan | 不证明真实clip与滤镜清晰度 |
| G2 归档集成 | class/helper可加载、目标调用走新链、无旧二次切块、两种资源模式匹配；非目标路径未意外改动 | 不证明实际输入和事件时序 |
| G3 场景回归 | 打字/补全/下一页/跳过/自动播放/取消/重入、槽位全可达、事件次数与基线一致、真实clip及CRT下可读 | 单一正文通过不代表61类全通过 |
| G4 交付身份 | 已验收归档SHA与安装器载荷一致，完整组合可回退 | 不以安装成功替代G3 |

每个场景独立标记`未适配 / 候选 / 阻塞 / 已验收`，保存失败样本和构建身份。P1只在所选正文链、存档、道具各自通过G1–G3后闭环；P2按覆盖台账逐入口推进，不把未适配场景算作全游戏通过。这里规定的是后续验证设计，不表示本轮已执行测试。

## 10. 本次完善的验收标准

1. 必读中文不使用8px作为最终显示方案；10px在实际CRT/倍率下仍需人工可读性确认。
2. 文字墨迹和效果范围不超过分配矩形；相邻字段/行不相交，非选中列表摘要有完整查看途径。
3. 8字中文名字、最长道具名、最大数量/时间、纯英文与中英混排分别测试。
4. 所有列表项/存档槽在减少可见行数后仍可访问；上下选择、滚动、确认与命中区一致。
5. 动画在所有显露边界位置稳定；自动断行不产生英文长词连字符，不丢句末标点。
6. DS新增显示页不提前完成逻辑节点；原选择、交易、存档内容与输入规则不因排版变化而改变。
7. 独立检查：无邻字重叠、无邻列碰撞、无行间压字、无意外父裁剪、无后画背景遮挡。
8. default与classic分别核验；只修default不算菜单通过。
9. 当前安装包与测试包身份一致；字体定义与图集必须配套。背景位图单独变更时保留帧身份和其他美术。

10. 最终文本变换与索引映射有入口证据；显示子页不会重复事件，自动字幕溢出不以不可读的轮播或截断掩盖。
11. 原class身份不匹配、字体/布局组合缺失或目标补丁不完整时，构建与验收明确失败；不存在悄悄沿用旧中文布局的“成功包”。
