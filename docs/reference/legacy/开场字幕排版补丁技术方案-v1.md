# 开场字幕排版补丁技术方案 v1

> 设计日期：2026-10-23。目标版本：Cosmobreeder Yiffai `1.0.5_full`。
> 状态：**设计稿，未实现、未构建、未做本轮游戏/JVM验证**。本文件保留为 ClassicPreTitle 8条字幕的局部原型；总体研究范围与实施路线已扩展为[全游戏中文排版研究与补丁总方案](<全游戏中文排版研究与补丁总方案.md>)，不再以开场代表全部工作。
> 本方案不包含存档恢复、存档重定向或隔离修复，也不以它们作为排版工作前置。验证记录不得因此标为“存档隔离通过”。

## 1. 决策摘要

采用 **“局部字幕适配器＋全文像素布局＋原打字机显露索引＋原整行绘制”**。

1. 先在现有中文验证基线上只替换字幕布局，保持 12px 中文字形、16px 行步进和现有终端/CRT效果，单独证明裁切修复。
2. 新布局控制自己的行循环，不能继续依赖旧的字符配额循环；短句也必须能够从原来的一行变成两行。
3. 原逻辑字符串和打字机时间表不变；优先使用恒等索引映射，只有证实存在上游格式化产物时才建立非恒等映射。
4. 测量和绘制使用同一实际字体实例。固定行起点，逐行绘制已显露前缀；不将未显露汉字换成窄空格后重新排版。
5. 正式交付采用旁置 INI＋加载器 JAR＋自定义 PAK；在第二个独立阶段迁移到独立字体纹理，保留原主美术图集。
6. 普通 UI、地图、命名栏及 CRT 笔画保护属于后续工作包，不混入首轮几何修复。

**不采用**：缩成 8px、横向压缩、删字/删标点、全局改 `String.length`、全局将 8 改为 12/13、只改 FNT 行高、只替换最后一次 Id 调用、在屏幕最后覆盖一层高清字幕。

## 2. 基线与问题证据

### 2.1 已确认事实

- [验证报告](<../localization/reports/planning/opening-verification-20261023-v1/report.json#L303-L426>)：8 条中文均出现，7 条右侧裁切，只有脚本 L7 完整；长句已有两行但第一行仍裁切。
- [字体指南](<字体渲染逆向与补丁指南.md#L164-L177>)：中文 advance=12，ASCII/空格通常为8；字库 lineHeight=13，但 VSN 的行定位另外使用16。
- [jo 分行现场](<font-evidence/snapshot/jo.txt#L148-L178>)：当前先按字符配额切块；行定位是 `x=jo.e`、`y=jo.f-16×lineIndex`；结束提示另按 `jo.e+amq.a()×8+2` 定位。
- [整行绘制重载](<font-evidence/callers/Id.txt#L284-L301>)没有逐字加8。固定8格逐字入口属于其他重载，不能用它替代字幕入口。
- [底层入口](<font-evidence/snapshot/arq.txt#L747-L789>)设置 wrap=false；上层不能依赖它自动按文本框宽度换行。
- 只读 SHA 对照已确认：原备份和开场验证副本的 `PRG/jo`、`PRG/amw`、`PRG/Id` 均与保存的字节码快照一致。这轮验证没有修复上述布局类。

按当前[字体定义](<../localization/runtime/bbc2.fnt>)重算候选原串的 advance 总和如下。这不是最终布局宽度，更不是非透明墨迹范围：

| 脚本行 | 字符数（当前全部为BMP） | advance 总和 |
|---|---:|---:|
| L6 | 21 | 252 |
| L7 | 22 | 244 |
| L13 | 23 | 256 |
| L14 | 24 | 280 |
| L20 | 24 | 288 |
| L21 | 25 | 292 |

L7 的 advance 总和超过报告中的240预算指标，但截图仍完整。这正说明：**预算指标、advance、字框和可见墨迹不是同一个量**。240不能直接登记成已经量到的容器内宽。

### 2.2 设计不冒充已知的事项

以下必须在实现阶段测定：实际字幕安全矩形、当前 amq/amv 值、8 条文本各自进入 `amn` 后的完整字符串、旧格式化插入字符的位置、活动脚本身份如何传递到字幕实例。不得根据类名或画面估算把它们写成既定常量。

## 3. 首版范围和发布边界

### 包含

- 精确白名单：ClassicPreTitle 脚本 L6、L7、L13、L14、L20、L21、L28、L32，身份以资源与候选内容哈希为准，行号仅辅助定位。
- 中文/ASCII混排、方括号、句末标点、双省略号；最多两行是首轮候选约束，需通过实测容器验收。
- 正常显露、跳过显露、重复进入片头、自动切换、fade/场景顺序、完成提示兼容。
- 对未命中白名单的文本保留原逻辑。

### 不包含

- 接纳译稿、全量翻译、通用剧情分页、任意输入字符、全UI覆盖、存档功能改造。
- 自动修改 `auto` 参数或剧情时序；画面溢出不能通过延长时长、提前切页或删除内容暗中解决。
- 首阶段 shader 修改、世界分辨率修改、全局字体注册替换。

8 条候选仍为 `not_accepted`；排版验收与翻译接纳是两个独立状态。

## 4. 模块设计与数据流

以下名称都是**拟新增组件/数据结构**，不是现有游戏 API。

```text
原资源 / 候选译文
   ├─ 原解析与格式化 → 原 amn 动画串与时间表 → 原 amo 回调
   └─ SourceBinding：资源身份、显示文本、动画串校验与索引映射
                                      ↓
                    VsnAdapter：白名单与实例上下文
                                      ↓
                    LayoutEngine + FontMetricsBridge
                                      ↓
                    不可变 LayoutPlan（按全文构建）
                                      ↓
             每帧 revealIndex → 各行 visiblePrefix
                                      ↓
             原 SN 整行绘制 → 原终端效果 → 原 CRT
```

| 模块 | 输入/输出 | 责任与限制 |
|---|---|---|
| Bootstrap/Manifest | 基线指纹、资源/代码清单 → 全有或全无的激活状态 | 不在每帧读包；不将探针直接当生产加载器 |
| SourceBinding | 原稿、原格式化输出 → DisplayDocument与索引映射 | 只移除有来源证明的排版填充，不猜空格用途 |
| VsnAdapter | 实例、原回调参数、字体角色 → 新绘制或原逻辑 | 不更改原完成布尔、事件和动画时间表 |
| LayoutEngine | 完整显示文本、实际度量、profile → LayoutPlan | 确定性换行、标点约束、完整内容检查 |
| FontMetricsBridge | 当前字体实例、候选行 → 度量快照 | 与绘制使用同一实例；不缓存引擎池中临时对象 |
| TextBackend | 固定行计划、显露索引 → 原绘制调用 | 每行一个字符串；不走 Id 的固定8格逐字接口 |
| Diagnostics | 匹配、行框、索引、错误码 → 有界日志 | 不输出用户存档、凭据；失败不伪装成排版通过 |

### 4.1 数据契约

```text
DisplayDocument
  sourceKey: rootHash + eventId + candidateHash
  displayText: 完整可见文本（不含自动排版填充）
  animatedTextHash: amn.a() 的预期完整值摘要
  sourceSpans[]: display UTF-16 span → animated UTF-16 span
  generatedSpans[]: 旧格式化产生的字符及生成原因
  fontRole / normalizationRevision

ContainerProfile
  profileId / revision / sceneIdentity
  verifiedClipRect / padding / effectInsets
  originalAnchor / lineStep=16 / alignment=LEFT
  maxLines / overflowPolicy=REJECT / hintRect

LayoutPlan
  sourceKey / animatedTextHash / fontRevision / profileRevision
  lines[]: displaySpan, fixedOrigin, baseline, advanceWidth,
           glyphBounds, inkBounds, effectBounds
  revealMap[] / hintAnchor / contentCoverage
  status: FIT | OVERFLOW | MISSING_GLYPH | UNBOUND_SOURCE
```

索引端点采用半开区间。原始索引仍是UTF-16码元，不改成像素或字数。缓存键不包含每帧掩码串或显露进度；字体、全文、profile、语言改变时失效。按字幕生命周期清理，并加容量上限，不以静态强引用无限保留实例。

## 5. 精确接入点：替换整段分行，不只改最后一个 draw

### 5.1 首要接入方法

[jo 七参静态回调](<font-evidence/snapshot/jo.txt#L148-L229>)：

```text
a(LPRG/jo;Ljava/lang/String;LPRG/azK;LPRG/amn;ILjava/lang/String;Z)V
```

| 参数位置（从0计） | 用途 |
|---|---|
| 0：jo | 包含绘制接口、原坐标、配额等上下文 |
| 1：String | 原代码用于 Fox/HardFox 字体选择；**不当作正文** |
| 2：azK | 保留原提示/时序判断 |
| 3：amn | `amn.a()` 提供真正的完整动画串 |
| 4：int | 原 amo 计算的显露索引；原回调未消费，补丁需要开始使用 |
| 5：String | 当前掩码串；仅用于一致性诊断，不作为新布局输入 |
| 6：boolean | 原完成判断结果；保持原语义 |

实施操作：

1. 对原方法 PC0–36 的旧“掩码串按N切块＋遍历绘制”区域，引入白名单分支。
2. 未命中范围：执行原分行逻辑；命中：由新适配器完整遍历 `LayoutPlan.lines`，旧分行循环不再执行。
3. PC37–65 的提示坐标计算，对命中范围改用 profile/布局锚点；非命中仍保留原值。
4. PC67以后与完成判断、事件、时间及闪烁有关的逻辑保持语义与执行次数一致。不得因命中新布局提前return而跳过这一尾部。
5. 字体角色条件照抄原判定的语义，不把 Fox/HardFox 分支统一当作 default。
6. 新分行块结束时保持操作数栈为空，原局部变量0–6的类型/语义不变；提示所用locals 8/9仍初始化。偏移变化后重建后续所有分支与StackMap，而不是直接拼接字节。
7. 全游戏补核已确认原 `aEO.f(azz)V` 为同步顺序遍历，见[实际方法](<full-layout-study-20261023/supplemental/ds-limits/PRG_aEO__4f434112a6cd.txt#L762-L778>)。新调度应保持该顺序；这不替代对其他回调或合成目标的验证。

**为什么不选三字节 Id 调用重定向：** 最后一次绘制调用只收到旧的一行、字体分支和坐标，缺少全文与显露索引；更重要的是调用次数受旧循环控制。首句需要从一行变两行时，单改这个调用不能自然生成第二行。正式方案因此接受有界方法改写和 StackMap 重建，而不是为了等长补丁保留错误行数。

### 5.2 私有访问与测宽入口

[jo 字段](<font-evidence/snapshot/jo.txt#L4-L12>)和[Yg 字段](<font-evidence/snapshot/Yg.txt#L4-L8>)含 private 成员。把 helper 放在 `PRG` 包内**不等于获得 private 访问权**。

- 由被改写的 jo 自己读私有字段，再将必要值传给 helper；或在 jo 内新增唯一命名的桥方法。
- 在 Yg 内新增窄的字体/测量桥，利用其已有字体注册表取实际实例；不把全部文字重载替换掉，不拦截图像 String 重载。
- 如需同包访问包级字体数据，helper 必须与游戏类属于同一个实际运行时包/定义加载器；部署时验证，不能仅凭包名相同推断。
- 不使用每帧反射，不以全局关闭访问检查作为补丁前提。

## 6. 旧格式化与打字机：保留逻辑，拆开显示

### 6.1 基准选择

[amo](<font-evidence/callers/amo.txt#L34-L73>)使用 `amn.a()` 生成掩码；[amn](<font-evidence/callers/amn.txt#L41-L109>)保留自己的显露进度算法。因此：

- 动画全文取 `amn.a()`，显露索引取原回调参数4。
- 不自行重算 elapsed/字符数，不重新解释 `auto(8.0)` 的计时语义。
- `amG.f()` 在当前证据中是字体/说话者相关字符串，不是已证明的同一正文。
- 原 `trim`、正则、时间表及完成比较保留，不修改原动画串长度。

### 6.2 首版的可实施过渡：8条精确 SourceBinding

必须区分两类空格：`amw.a(String,int)`在**amn之后**为逐字显露生成的掩码空格，新布局根本不消费它们，不需要为其建立删除映射；另一组[amw 格式化重载](<font-evidence/callers/amw.txt#L108-L318>)具有补空格、分页及自动连字符能力，但它们是否影响这8条`amn.a()`仍待确认。不能把“存在该方法”写成“这8条一定经过它”。

首版为8条候选构建有版本锁定的绑定数据，按最小必要复杂度选择：

1. 用原格式化路径的输入/输出捕获或无图形夹具，获得每条文本进入 `amn` 时的完整值、配额参数及转换过程。若与显示文本一致，采用恒等映射，不引入通用规范化器。
2. 只有发现amn之前的实际转换才建立非恒等span映射：原文本字符保留身份，自动填充/自动连字符标记生成原因；原本存在的空格、方括号、连字符不得误删。不通过 `trim`/删除所有空格猜测来源。
3. 检查旧格式化是否已截断正文；如已丢字则拒绝发布，必须将接入点前移到截断之前，不能在显示层“补猜”。
4. 对显示文本预先排版；每个显示字符关联原动画索引范围。仅当其原范围全部显露时，才显示该字符。
5. 运行时验证 `amn.a()` 与绑定预期完全一致。映射缺失、多义或角色/字体不符即标错，不模糊匹配。

若确有amn之前的自动填充，其位置保留原有动画时间消耗，但不占新画面的横向空间；没有这种填充就无需此规则。索引端点通过原 `amw.a(全文,index)` 的实际前缀行为逐点核对，不能把 `trim` 后长度擅自解释为已平移过的字符索引。原字符串不回写、不插入新LF或全角空格；这是兼容选择，不承诺优化原动画节奏。

场景绑定使用“活动脚本身份＋事件身份＋全文摘要＋字体/profile”。活动脚本/事件身份的传递入口尚待M0确认；不能以“含汉字”或“文本碰巧相同”替代白名单门禁。若M0无法建立身份链，先解决绑定，不扩大为全局补丁。

### 6.3 每帧绘制

```text
进入字幕：校验绑定 → 取得/创建全文LayoutPlan
每帧：  接收原revealIndex与done
        对每一条已确定的行：
          通过索引映射求可见前缀
          在固定原点调用原SN整行绘制
        继续执行原事件与提示逻辑
离开：  释放实例绑定/临时资源
```

先固定全文行边界，再取各行前缀；行原点不跟当前前缀宽度变化，首版只做左对齐。不为未显露字符补空格，也不逐字调用固定格入口。

## 7. 布局算法与容器策略

### 7.1 测量必须与实际绘制同源

本地 [arr 布局入口](<font-evidence/snapshot/arr.txt#L12-L59>)与[arq 实参](<font-evidence/snapshot/arq.txt#L747-L789>)作为依据，不使用未匹配版本的新版 libGDX 示例。

1. 由桥接代码取得当前字体，使用无自动wrap、无truncate的布局参数测候选行；只复制必要的宽度、run/glyph位置与度量。
2. 明确首字offset、末字宽度、kerning、scale和整数取整；不以 `length×12` 或单纯 `sum(advance)` 作为最终边界判定。
3. 不长期持有字体 draw 返回的临时布局，不借用其绘制缓存做持久状态。自主测量对象也按当前引擎生命周期清理run，避免池对象泄漏。
4. 同时计算 advance、字框、非透明墨迹及效果范围。布局容量采取保守字框＋效果边距；实际墨迹用于截图/像素核验，不依赖末尾标点“恰好透明”才不越界。
5. 对每个实际可见前缀，断言已显露glyph坐标与全文对应位置一致；若某字体/对齐模式不满足，不能继续使用前缀方案，需另立固定字形顶点提交路径。

### 7.2 换行规则

- 按字符/结构边界推进，记录最近合法断点；加入下一个元素会超过安全宽度时回退至合法断点。
- 句号、逗号、顿号、冒号、分号、问叹号、闭括号不孤立置于行首；开括号不置于行尾。
- `……` 成对处理；短英文/数字词组优先不拆。超宽长词允许字符级断开，不新增改变原文的连字符。
- 方括号作为现有可见内容/语义保留，不擅自启用底层颜色markup。普通断行不能删除它们。
- 没有合法且容纳得下的断点、单个不可拆单元超宽、需要超过maxLines时返回显式OVERFLOW；不无限回退、不静默裁切。
- 首版只接受已核验的BMP字符覆盖。代理对/组合字符不以“Java能读字符串”冒称可绘；不支持项在构建期阻断。

### 7.3 首轮 profile

逻辑画面为256×224。x/y先沿用原字幕锚点；实际可用宽度按 `verifiedClipRight - drawX - rightPadding - effectInset` 求得，并核对左/上/下边界。

**224px内宽、16px行步进、最多2行**仅作为首轮离线比较候选，不是已测量的正式常量。M0/M2应确认是否适用于所有8条和4个fade组；最长408 advance提示两行有希望，但不替代禁则和容器验算。

只有验证过的profile进入发行清单；禁止直接把报告的240指标或 `amq×8`当真实内宽。结束提示单独占位，与最后一行和画面边缘不相交；保留原显示条件及闪烁频率。

超出两行时，首版失败并给出所需宽高/行数。分页、扩大字幕面或调整时长另行设计，不能默认新增交互打断自动片头。

## 8. 字体、资源和正式交付

### 8.1 分两步，避免变量混杂

**布局实验阶段**：复用已验证的中文字库和扩页资产，只新增布局代码与绑定/profile。原验证证据保持不变，新建候选目录。不以实验归档作为正式发行物。

**旁置交付阶段**：从原版基线重新构建，保留原主美术图集；相同中文像素和度量装入独立字体纹理，注册专用字体角色。原 default/classic/dingbats 保留，不让未适配界面自动全局切换。

独立纹理的本地入口见[arp 构造器](<font-evidence/snapshot/arp.txt#L56-L76>)；其资源创建、拥有权和退出释放必须实际验证。使用项目已有预乘字库；不在本轮选择、安装新字体。来源与许可沿用[NOTICE](<../localization/runtime/NOTICE.txt>)及[OFL](<../localization/runtime/LICENSE-FusionPixel-OFL.txt>)，原游戏ASCII像素的分发权不由OFL代替。

以下为拟定交付名，不表示已生成：

- 启动配置沿用[已验证入口](<独立PAK交付与加载器验证.md#L8-L35>)；原EXE/JAR/官方PAK不改。
- 新PAK是加载器主动读取的容器，不是假定原游戏发现任意PAK。
- 字幕资源覆盖必须接入已确认的资源读取链。不能只在自定义ZIP放一个同名文本，就宣称原解析器能读到。
- 首版只实现8条资源的精确覆盖；资源桥的具体descriptor和“替换发生在解密前还是解密后”在M0锁定，禁止混用加密槽位与明文路径。

- 发行物避免捆绑完整原版class/美术归档；优先提供变换规则或本地重建所需增量。
- 合并已有INI，仅管理自己的入口。卸载不恢复/覆盖用户存档；更新要求退出游戏后进行，不设计运行中热更。

## 9. 版本锁定、类加载和失败处理

### 9.1 锁定链

沿用[输入身份](<字体渲染逆向与补丁指南.md#L22-L40>)，同时校验：游戏版本、两归档SHA、每个目标class SHA、方法descriptor、预期指令、资源与字库SHA、绑定/profile版本。

定位不依赖“搜索某个8”或仅凭方法名。混淆class大小写冲突保留ZIP精确entry，不将整包解到大小写不敏感目录再覆盖。

新增控制流的实现需重建分支、StackMap、异常表与max stack/locals；当前等长三字节补丁经验不能替代这项工作。构建工具/依赖版本在M0确认后锁定，本设计不假定已安装某个字节码库或编译器。运行时不要求玩家安装JDK。

### 9.2 启动与原子激活

建议状态机：`UNVERIFIED → PREPARED → ARMED → ACTIVE`；任一步失败进入 `REJECTED`。

- PREPARED：校验所有必需代码/资源，预计算变换；不能仅验证第一个类后就加载中文字幕。
- ARMED：helper已可见，必需变换器就位；变换只接受白名单、实际输入哈希与预期加载器。
- ACTIVE：资源与渲染入口共享同一激活状态。部分代码失败时不得继续发布中文资源并把英文旧布局当成功。
- 启动前不匹配可拒绝本次汉化启动，给出错误和关闭补丁入口的方法；关闭后仍可运行原版。
- 运行中若计划/绑定失败，记录显式错误、使本轮验收失败。开发模式可诊断性回到旧绘制，但绝不把它登记为修复成功；发行前所有8条须预检通过。

Java 17文档已确认：`premain`未捕获异常会使启动中止；但 `ClassFileTransformer.transform` 抛异常通常等效于返回null，后续类加载仍会尝试。**不能靠在transform里throw来实现可靠拒绝。** 预检在premain完成；晚期异常/冲突还需有经过故障注入验证的显式激活门禁，必要时由原应用进入补丁场景前的检查阻止继续，不依赖忽略掉的转换异常。

helper应在第一次解析引用前就对游戏定义加载器可见；不能等到NoClassDefFoundError后再补加载路径。系统加载器追加搜索仅在实测游戏使用该加载器时采用，不向bootstrap塞依赖游戏类的helper，不捆绑第二套libGDX，也不把原游戏class放进helper包造成覆盖竞争。

### 10.1 自动化测试

- **内容守恒**：拼接显示span应还原候选正文（只按明确规则处理结构标记），句末标点/括号不丢；自动填充删除均有来源记录。
- **索引边界**：每条遍历 `0..animatedText.length`，包括空串、首字、断点前后、末字、尾空白、跳过与done边界；不只抽5个进度点。
- **位置稳定**：同一行、同一glyph在所有已显露阶段坐标一致；换行计划缓存不因reveal变化重建。
- **几何**：全部行的字框/墨迹/效果范围在profile内；行间不碰撞，提示不遮挡正文。逻辑像素目标与最终CRT截图分开比较，不能直接对弯曲后的屏幕矩形套逻辑边界。
- **边界文本**：中英数字、原空格/自动空格、开闭括号、`……`、超长词、缺字、超宽单元；`|`/`<p>`/显式LF在首版未支持时必须明确拒绝绑定，不能静默吞掉。
- **错误注入**：归档/class/字库/绑定不匹配、helper不可见、必需变换未命中、资源缺失、未知字体、超两行；不能半启用或无日志降级。
- **原路径回归**：英文整行、原非目标字幕、default/classic/dingbats角色路由；专用字体不污染其他文字界面。

### 10.2 JVM与实机验证分开记录

1. 静态差分：原类只改白名单方法；原脚本非目标部分保持一致。
2. JVM验证：使用实际随包JRE进行类校验及必要链接测试；“加载但不初始化”不等于字体实际注册执行。
3. 实际初始化：helper可见、字体注册和首次实际draw均有证据；观察首次进入与再次进入。
4. 实机主矩阵：8条×0/25/50/75/100%代表帧，辅以逐字边界轨迹；每条保存最终完整帧。空白进度也登记事件，不假装空白截图能证明字形正确。
5. 跳过、自动切换、4个fade组、结束提示、场景退出分别检查；[原脚本](<../localization/sources/blobs/93f5c0dd1ffc4e76059f3d9e0d6eee36b28ea8ec11106b6343c76a9336ddaa33.vsn>)的音乐、fade、queue、sync及auto参数不被无意修改。
6. 3倍整数窗口为首个视觉验收点，4倍追加回归；2倍/非整数模式单列几何与可读性结果，不从3倍结论外推。
7. 性能记录布局构建次数、CPU时间、绘制次数及反复进出后的资源数；不预先承诺零开销。

发布门槛：**8/8全文完整、0越界、0非预期重叠、0显露位置漂移、原事件不重复/遗漏、非目标路径不回归**。几何通过不等于中文盲读通过，阅读质量另记。
