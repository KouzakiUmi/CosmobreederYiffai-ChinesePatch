# 全游戏中文排版研究与补丁总方案

> 研究基线：Cosmobreeder Yiffai `1.0.5_full`，2026-10-23。
> **本轮完成的是全归档静态调查、已发现入口的分类研究和总体设计；不是已实现的补丁，也不是全场景实机验收。**
> 本文是总体方案入口。[开场方案v1](<开场字幕排版补丁技术方案-v1.md>)降为VSN局部原型设计，不再代表整个补丁的研究范围。存档恢复/重定向不属于本方案；命名和存档界面的文字显示属于本方案。
> **2026-10-24实机反馈后的增量设计：** 以[10px与紧凑菜单完善方案v2](<中文排版完善方案-v2-10px与紧凑菜单.md>)作为近期实施入口。当前r21已使用10px默认字库但旧布局未改；必读中文不退回8px，先局部重排存档/道具与像素换行。沿现有JAR/PAK构建集成，本文的三文件交付、独立纹理及CRT增强不作为本次修复前置。

## 1. 主要结论

**不能通过“全局换字体＋统一改行高”完成全游戏汉化排版。需要统一布局核心、分场景适配器、独立字体角色和位图文字改造四部分。**

本轮补齐的关键事实：

1. 原归档7736类全部进入静态扫描；最终153处文字绘制/测宽入口调用，61个文字及字体基础设施直接消费者逐项有研究归属。数字不是界面数量，也不是运行覆盖率。
2. DS正文确实有自己的AST、分页与显示链，常规/窄版/商店正文分别采用20×3、12×3、28×3逻辑配额；VSN默认28×3，但外层流程不同。
3. 旧分行按字符/英文单词，连续中文还可能被“长词切分＋追加连字符”。必须在旧布局损伤内容之前接管，不能只在Yg末端补救。
4. 三参amw用`<p>`段落，四参amw用`|`；后者全归档11处调用、7类，不是一个卡牌界面的局部特例。
5. 单行绘制仍会来自已预排的多行正文。独立逐字路径至少有Id、ME、Jq、Jv四组；独立字符数居中至少有Yg、kn、Po三组。
6. `classic`有真实菜单/确认/成就消费者；default、classic、dingbats必须保持不同角色，不可只给default塞中文。
7. 菜单标题、列标题、操作提示、UPDATED标识有烘焙在位图里的文字，动态字体补丁不会覆盖它们。
8. 全文稳定布局必须在最终文本转换后生成，并保留原UTF-16索引映射。Tc、SA页后变换和toUpperCase都会影响取值或最终显示，不得默认为原文直通。

## 4. 必须采用的总体架构

```text
源身份：资源根/DS节点/字典键/代码位置/位图帧
                ↓
Scene Adapter：保留条件、控制标记、变量、字体角色
                ↓
DisplayDocument：最终文本 + 结构标记 + 原索引映射
                ↓
LayoutEngine：真实字宽、禁则、行/页、字段、对齐
                ↓
LayoutPlan：固定glyph位置、行页、光标/高亮/命中区
                ↓
Renderer：原合成顺序中按显露索引提交
                ↓
原终端效果 + 原CRT（可读性增强另阶段验收）
```

### 4.1 统一核心，不统一所有控件行为

所有适配器共享实际字形度量与基础断行，但不共享一个硬编码宽度或行高。Profile至少包括：真实内容矩形、padding、效果边距、基线、字体角色、对齐、字段列、最大页高、溢出策略、可交互区域和最终输出模式。

保留三套独立概念：**数据/控制索引、显示字符/字形、像素位置**。共享String.length、原剧情key、数字逻辑不改成像素。

显示身份不以“文本含汉字”或“字符串相同”决定。使用源根/节点或事件、出现位置、消费方法、语言/角色与profile共同绑定；同一译文出现在两个框中可以有不同布局，不能改共享单元只迁就一个位置。

### 4.2 文本转换必须位于布局缓存之前

DS至少经过Tc取值、可能的SA页后变换和显示前uppercase；字典也有English/Reverse/AlBhed模式。适配器须明确哪些是内容转换、哪些是旧排版填充，生成最终显示文本后再测量。

- 无转换时使用恒等映射，避免无必要的通用规范化器。
- 有转换时追踪原UTF-16 span→显示span→glyph；自动填充、连字符与原有内容分别标记。
- 原逻辑字符串、原动画完成判断和剧情事件保留；呈现页可以增加，但最后一页完成前不能提前触发原节点完成事件。
- 不得从已经截断的结果猜回正文。若旧预处理会丢字，接管点必须前移。
- 缓存键包含全文/变量快照/字体/profile/语言模式/必要Locale，不包含每帧显露掩码；动态变量或变换结果变化时失效。

### 4.3 字体角色

| 原角色 | 中文策略 | 必须保持 |
|---|---|---|
| default | 独立CJK字库角色，保留原ASCII像素/度量 | HUD数字、固定图案和未适配路径 |
| classic | 保留菜单风格的中文角色；独立校准基线/行框 | 原classic特殊等宽设定、选中状态、菜单尺寸 |
| dingbats | 按剧情语义保留替换字形分支；覆盖不足显式登记 | 不能统一映射到default而抹掉原效果 |
| 数字/键位/图标 | 继续既有等宽或图像路径 | 不因中文正文扩宽改变数值列和符号身份 |

采用独立纹理、主美术图集保持原尺寸，避免把所有场景绑到扩大的共享纹理。正式字库扩大覆盖时同步校验正文解析白名单、缺字策略、许可和内存生命周期。已有字库不代表任意玩家输入或扩展区汉字均支持。

## 5. 按场景实施，不做全局常量补丁

### A. 剧情类：VSN＋三类DS一起列入设计

- 对VSN接管jo的整个分行输出区域；对DS分别接管JR/Nb/Kl的正文预排以及JQ/Na/Kk的显露呈现。
- 新循环由LayoutPlan控制行数，不能只重定向旧循环最后一次draw。
- 正文分页按像素容量与结构段落，不再依赖英文长词断开；`<p>`、`|`等只由各自适配器解释一次。
- 名字区、正文区、选项、结束提示分别布局；显示页状态与原剧情节点状态分开。
- 自动字幕保持原控制时序；过长译文先构建期拒绝或制定场景级分段/回读方案，不默默缩字、删字、加省略号。

### B. 菜单与多字段：先拆空格对齐，再布局

- 将“名称＋空格＋数字＋标记”拆成字段run，分别指定对齐与边界。
- 非正文单行标签可省略的前提是有手柄/键盘可达的完整内容视图；关键选择差异和剧情正文不得被省略隐藏。
- 行距或容器高度变化后，同时更新选择框、滚动范围、鼠标/手柄命中区，不能只改变字形坐标。
- 不只改Id：ME/Jq/Jv的独立逐字输出以及kn/Po的自算居中都要单独接入。
- 8字名字是逻辑限制，64px是显示限制；保持前者不等于必须保留后者。优先重新分配列宽，空间不足时焦点显示完整名称，绝不改存储内容来让截图放得下。

### C. 位图：作为同一补丁的独立工作流

已确认含文字的背景必须进入资产表，而非等到动态字体完成后才发现漏译。原图尺寸、Alpha/色通道、调色、帧时序、图集偏移和相邻美术均为约束。

8px高微型标签无法同时满足原生12px中文、不压缩、原框不变：必须选择局部重排或等义图标。品牌与不可读微标签不机械翻译；动画每个不同帧须核验，不能用首帧代表整组。

## 6. 补丁组织与交付

正式结构仍采用[已验证装载路线](<独立PAK交付与加载器验证.md>)：旁置INI＋启动加载器JAR＋自定义PAK。原EXE、主JAR、官方PAK不改；此路线的探针通过不等于正式加载器已经实现。

拟新增模块：

```text
bootstrap / manifest           基线校验、白名单变换、原子激活
source-bindings                资源/节点/出现位置到显示身份
layout-core                    度量、禁则、结构段落、行页与字段
adapters/vsn                   jo与VSN预处理
adapters/ds                    JR/Nb/Kl及JQ/Na/Kk
adapters/widgets               列表、确认、卡牌、HUD、命名等
font-roles                     default/classic/CJK/符号角色
bitmap-overrides               固定图与帧级替换
profiles                       逐显示面容器与交互配置
verification                   静态、JVM、场景、视觉、回归矩阵
```

模块名是拟定职责，不是已经存在的目录或API。

原类只注入必要桥接；private字段应在所属类内读取后传helper，不认为“同包”就能读取private。复杂方法改写必须正确重建分支/StackMap/异常表；新增helper在首次引用前可见。

版本锁定包括原归档、目标class、方法descriptor/预期指令、资源、字库、profile和布局schema。任何一项漂移拒绝半套启用，不把原绘制的诊断回退称为汉化成功。

启动代理的Java17契约沿用[开场方案的文档核验](<开场字幕排版补丁技术方案-v1.md#L277-L293>)；特别是transform里抛异常不自动阻断类加载，原子激活不能只靠throw。工程实施仍须在实际随包Temurin 17.0.6+10验证。

## 8. 验收矩阵：全游戏必须按来源和显示面交叉

### 8.1 数据与结构

- 全部67个有效VSN根、2个DS根进入构建检查；按资源组覆盖规则，不能重复统计JAR/PAK同名根。
- 每个翻译单元的全部出现位置都映射到显示profile或明确未覆盖项；字典键、代码位置和位图帧使用不同身份体系。
- 保留条件、命令、控制标记、动态变量；原文/译文守恒，不靠删字或自动连字符凑宽度。
- 字库覆盖及解析接受分别检查；未知字符明确报错，不静默跳字。

### 8.2 布局与动画

- 测量与绘制采用同一实际字体、相同advance/kerning/offset/scale/取整；墨迹和描边都在容器内。
- 对每个动画文本遍历全部显露边界，已显露glyph的位置不随后续出现而变。
- 句末标点禁则、中英混排、显式段落、长词兜底、空串、空页和尾空白各有测试。
- 多列、光标、选中高亮、结束提示、滚动分页及命中区与布局结果一致。
- 默认/窄/商店DS、新旧页数差异、最终确认、跳过与自动播放均不重复或漏触发逻辑事件。
- 大写化、语言替换及动态变量长度变化后，源索引映射和缓存失效正确。

### 8.3 图像与风格

- 位图文案逐不同帧核验；透明/调色、图集定位不破坏其他美术。
- default/classic/dingbats分别验收；纯ASCII数字/键位/图案回归。
- 普通终端和VSN效果不同，两个8周期规则不可互换；所有画面保持原遮挡/fade顺序。
- 3×和4×整数输出、2×、非整数、HiDPI分别报告。Nearest纹理不能替代最终输出验证。
- 与原版/无保护参考比较可读性和性能，不把一次截图或一组离线shader样张当全游戏保证。
