# R9 裁决口径（主代理）

两路提案都只是输入。裁决以英文原意、项目参照和容器事实为准，不以「哪一路更权威」或「字数更少」作依据。

## 一、逐条核对顺序

1. 读该行所在整场的英文与当前中文，确认问题真实存在（不是把已修项重报）。
2. 查该行是否已被 R2／R5／R6／R8 裁决或修改；已裁决项只在有新证据时重开，否则 `reject` 并在理由里写明。
3. 判断 `proposed_zh` 是否：意思更准、衔接更顺、口吻更贴人物；三者至少一项成立且不牺牲其余。
4. 结构核验：前缀、缩进、方括号、`@` 占位符、`<3`、数字与频率、`Lect`、`OTP` 不变；不引入空→非空的行。
5. 行宽：按剧情框 240px／12px 估算，超过 260px 的候选逐条用实际字形宽度复核；超限则压缩或 `hold`。

## 二、两路冲突时

| 情形 | 处理 |
| --- | --- |
| 两路文本相同 | 仍核一遍再 `apply`（一致不等于正确） |
| 两路不同、一方明显更准 | 采纳该方，理由写清差异判据 |
| 两路都只改了一半 | 自拟合并稿，`reason` 标注「合并两路」 |
| 两路都偏（过度改写、丢信息、加戏） | `reject` 或 `hold`，写明缺什么证据 |
| 只有一路提 | 独立判断，不因「另一路没提」而降权 |

## 三、必须拒绝的提案

- 改动英文、控制行、说话人、行号结构或占位符。
- 把 `current` 为空的合句尾行填成新句（台账机制直接拒收）。
- 新增剧情、动机、亲属／恋爱定论、口癖，或提高性化／粗俗程度。
- 把角色说辞写成客观事实，或提前揭示后续信息。
- 仅为「更文雅」而重写已经通顺且保真的句子。
- 重提已裁决人名、术语与谜题提示。

## 四、留档

每条决策写进 `batch-01/review/decisions.tsv`：`finding_id / route / severity / category / scene_id / row_id / decision / final_zh / reason`。`decision` 取 `apply`、`reject`、`hold`；`final_zh` 只有 `apply` 才填，且必须是完整物理行。

两路未覆盖但主代理在通读时新发现的问题，另起 `finding_id`（`R9M-001` 起），在 `route` 列写 `main`，同样走 `apply/reject/hold`。
