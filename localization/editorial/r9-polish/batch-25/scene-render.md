# 用引擎自己渲染：离线场景模拟

这份记录回答：**玩家实际看到的分页长什么样。** 答案不是靠复现规则推出来的，是把候选 jar 里的 `DialogueWrap` / `DialogueGrid` / `PixelLayout` 直接加载起来跑出来的。

## 为什么不再复现

batch-25 前几版用 Python 复现折行规则，错了两次：

1. 第一版按纯贪心（累加到 240px）；
2. 第二版按 `PixelLayout` 的标点禁折规则，但把容器认错了（以为是原版 `amw` 的 28 列硬切）。

两次都靠读代码推断。核验方两次都指出了问题。正确做法是**别再推断**——加载真实类，让它自己算。

## 工具

`tools/SceneRender.java` + `tools/scene_render.py`。

```bash
javac -encoding UTF-8 -cp <candidate>/cosmobreeder-multi.jar -d <tmp> tools/SceneRender.java
java -Dfile.encoding=UTF-8 -cp "<candidate>/cosmobreeder-multi.jar;<tmp>" \
     SceneRender <candidate>/cosmobreeder-multi.jar in.tsv out.json
```

输入 TSV 是 `key \t archive \t entry \t line \t body`，输出 JSON 给出每个用例的分页：`grid`、`pixelWidth`、`lines`、`breaks`（跨行字符对）。

全库 17,890 行渲染耗时 0.6 秒。

## 引擎实际行为（跑出来的，不是读出来的）

以 `[其他特工已经画出你所在区域的地图，有的带标注。]` 为例：

```
[20] [其他特工已经画出你所在区域的地图，有的
[ 5] 带标注。
[ 0]
```

三条事实：

1. **满行 20 个汉字**（12px × 20 = 240px）。所以断点位置由「前面有几个字」决定，改文案只能移动它。
2. **行首不出现标点**。`，`、`。`、`！` 会被拉到上一行末尾——这是 `PixelLayout.legalBoundary`。
3. **每页 3 行**，不足补空行。`formatCapped` 的 `q=28` 是 UTF-16 上限，对汉字文本不生效（20 < 28），只有拉丁字母多的行才会碰到。

## 用它量出的结果

| 范围 | 改前（candidate52） | 改后（candidate54） | 变化 |
| --- | ---: | ---: | ---: |
| 本批 96 行 | 92 处 | 35 处 | −57 |
| 全库 17,890 行 | 349 处 | 292 处 | −57 |

全库 17,890 个用例**零引擎错误**——没有一行触发溢出异常。

（数字与之前 Python 复现的 950→901 不同，因为那是按「跨行两字组合出现 ≥30 次」全量统计，包含了断在完整词之后的情况；这里统计的是引擎实际输出。）

## 剩下 292 处是真的切词

引擎输出里逐条看，都是实词被切开：

```
哦，你好呀，现在太热了，什么生意都做不 / 了！
要是现在能弄到一瓶冰镇 ICECOLA 就好 / 了……
不能怪你。这下面热得要命，根本没法做生 / 意，对吧？
快点回来！这无聊的房间我真的快待不下去 / 了！
你得有钥匙！我已经……什么办法都试过 / 了……
这个？就是那帮可爱太空崽子随身带的电击 / 枪。
```

共同形态：**行尾只剩 1～2 个字**，把「不了」「好了」「生意」「去了」「过了」「击枪」的末字挤到下一行。

这是 20 字硬边界的固有产物，不是判据误报。要修只能重写句子让字数落在边界前，边际收益很低——这 292 处分布在约 250 行，每行都要单独调字数。

## 这套工具能做什么

- 任意候选、任意文本，立刻看到玩家视野里的分页；
- 验证「行首不出现标点」是否成立；
- 量任意批次的排版改动效果，不用再写规则复现；
- 未来做卡面（16 列 × 128px）、数据书（224px × 3 行）时同样适用，只要换成对应的入口方法。

## 未做

- 只渲染文本层，没有画对话框边框、背景、角色立绘与动画。这些不影响折行，但影响「实机观感」。
- 没有在游戏进程内跑。这是离线加载同一批类，输入是归档里的原始字符串。
- 排版以外的验收（语义、结构、实机安装）不在本工具范围。
