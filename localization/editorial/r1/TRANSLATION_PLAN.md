# 中文重写精校方案（首轮）

## 一、目标：按意思与人物重写，不按英文句法描摹

读者应能连续读懂人物在回应什么、为什么转折、何时认真、笑点在哪里。允许改变中文句式、语序、拆并句和习语表达；不改变剧情事实、角色意图、玩法条件、施受关系、信息揭示顺序和原作的调侃尺度。

“基本译对每个词”不是通过条件。若整段中文不成立，即使单句勉强能解释，也须进入应改清单。相反，已经自然且保留人物差异的译文不为制造改动而重写。

## 二、只参考 WoC 的执行方法

参考其[现役审查流程](<../../../../WoC-ChinesePatch/docs/workflows/review.md>)和[工单式流程](<../../../../WoC-ChinesePatch/docs/proofreading-workflow.md>)中的：证据参考库、完整分块、问题分级、逐条决策、复审驳回留档、应用前 dry-run。

不套用其奇幻小说文风、现代词禁用表、角色敬语、专名、空 speaker 判定或 Ren'Py 构建／标签规则。本项目自己的[初翻与两轮精校约定](<../../docs/翻译与两轮精校流程.md>)仍用于保护稳定 ID、来源和两轮记录；当前用户明确要求的中文自然重写是新的内容质量目标。

本轮冻结对照的是已构建候选的当前中文，而非只看修前逐条草稿。

- 原 catalog：8,973 单元，10,385 出现位置。
- 原 JAR 自身 SFW 来源：7,134 条记录；单独保留，不把 PAK 译文无条件套入。
- 合计来源记录：17,519 条。只有整块源文、当前中文及控制上下文均一致的版本才合并阅读实体，仍保留各自别名和来源 ID。

## 四、三本参照，证据优先

1. **角色与关系**：谁在对谁说话、自称与称呼、资历与亲疏、正常语气、危急或被调侃时的变化，以及不能外推的限制。
2. **世界观与术语**：设定事实／角色自述／传闻分层；科技、装备、能力、地点按语境解释，多义词不按单词全局统一。
3. **剧情与知识时点**：主角平行线、版本差异、条件分支、动作顺序、早已知道与本段才揭示的信息。文件顺序不当作固定游玩顺序。

参照不是角色模板：不能因为毛瑟容易紧张，就把所有技术说明写成结巴；不能因为汤姆猫爱调侃，就让紧急救援仍然耍贫嘴。匿名或 VSN 元数据不能替代真实演出与前后文。

参照均保留稳定单元／位置和原文锚点；没有证据的关系和设定列为待核，不靠中文读着顺就补写。

## 五、逐段重写法

每场景固定走以下七步：

1. **复述意图**：用一句中文概括这段要传达什么、哪句是回应或笑点。
2. **锁住事实**：列出角色、对象、否定／程度、条件、动作施受、关键名词和不可提前透露的信息。
3. **连读现译**：暂时不盯英文，判断中文对话是否像有人在交谈、叙述是否连贯。
4. **重写整段**：按中文信息顺序组织，允许省代词、提前条件、拆定语、改主动表达、改习语；不要逐行保留生硬句架。
5. **放回人物**：检查资历、自称称呼、专业与闲聊切换、情绪强度，避免全员同一种“译者口吻”。
6. **倒查英文**：确认未漏转折或笑点、未把猜测变成确定、未把听错／被打断补成已说完。
7. **再看结构**：当前整句落在哪些节点、是否经过合句、是否跨条件／动作／换人。段落提案不是可直接写回脚本的节点表。

### 典型判断原则

- 英语跨框断词应恢复完整中文意思，不能让“回收—系统”“位于—在”式碎片继续支配中文。
- 真正口吃、被打断、信号杂音、故意改口有不同功能，不能把所有短横线统一删除或统一译成结巴。
- 习语若承担后句笑点，必须连同后句一起重写；只把习语改成通顺解释却丢掉铺垫，也不合格。
- 无线电 `come in`、`over`、`negative` 依通讯用途译，不取字典第一义；同一句普通场景仍可能另有意思。
- 男女主的亲属称谓看谁实际发言、对谁说，而不是仅凭文件名替换“姐姐／弟弟”。
- 双关可另列两种自然中文方案及损失说明；不能用译者长注解释笑点来冒充台词。

## 六、阶段与本轮交付

| 阶段 | 做什么 | 通过条件 |
| --- | --- | --- |
| R0 文档整理 | 冻结源与当前中文、建立角色／设定／剧情参照、完整工单 | 来源可追踪，事实层级清楚，版本不混用 |
| R1 全文粗校（当前） | 按完整审读块找 A/B/C 问题，提出自然中文短段重写稿 | 全包实际通读有收据，问题有依据，未读与用途待核另计 |
| R2 整段精修（后续） | 逐场景裁决并重写，形成逐实际输出节点的映射 | 意思、口吻、衔接和保护字段同时成立 |
| R3 二审（后续） | 对照源文与参照独立复核，接受／修订／驳回均留理由 | 发现有闭环，合法变体不被反复错误统一 |
| R4 技术与实机（后续） | dry-run、回填、字体与排版、脚本与分支、游戏实测 | 数据、运行时、画面与实际输入分开验收 |

本轮只交 R0 + R1，不修改正式译文和现用归档，不打包部署新文案，不把 proposal 改成 approved。

## 七、工单优先级与验收

- A：误义、人物关系、施受／否定、玩法提示、条件与揭示顺序、结构保护错误。
- B：段落衔接、翻译腔、语用与笑点、角色语域／称呼、语境术语。**这是本轮主体，不降为“可有可无”。**
- C：语义口吻都成立后的节奏与文笔打磨。
- Q：来源或用途待核状态，可与风险等级并列；不擅改、不掩盖未知。

发现记录详见[工单协议](<WORK_ORDERS.md>)。自动校验检查身份、收据与字段完整，不证明语义正确。完成通读、发现复审、正式应用、实机通过分别统计，不用一个百分比替代整个流程。

## 八、后续精校的执行批次

优先处理：

1. 任务开场与无线电教学：信息关系清楚，先修关键操作与连续问答。
2. 核心人物往来与亲属／身份揭示：先统一事实与称呼，再打磨互损和情绪。
3. 关卡救援与条件分支：不把互斥状态写成连续事件，不弄反动作施受。
4. 图鉴、装备和能力说明：玩法正确且中文完整，名称／说明与对话互相校验。
5. 结局与平行版本：人物实际发言和信息回收优先，不能按路径机械改亲属词。
6. 其他风格与文笔：在前述口径稳定后逐段精修；疑似代码实显或遗漏图像另开有证据的工单。

每批先给“完整原文段—当前段—重写段—逐节点计划—理由”，复审后才应用。不同角色、版本或多义词不做无语境的全局正则替换。
